# 看影音 README 重写设计

## 目标

为独立项目“看影音”编写全新的 README。内容以看影音 2.0.5 当前源码、Windows 产品定位和交付方式为唯一功能依据，不沿用旧项目的章节结构。文档以普通用户能够快速理解为第一目标，同时为开发者保留必要的构建和许可证信息。

## 受众与语气

- 主要受众：希望安装和使用看影音的 Windows 用户。
- 次要受众：准备阅读、构建或修改源码的开发者。
- 使用简体中文，表达直接、克制，不宣传尚未实现的功能。

## 内容结构

1. 项目名称、图标和一句话定位。
2. 当前支持范围：Windows 10/11，使用 MSIX 交付。
3. 当前功能：本地媒体库、OpenList、TMDB、播放器、字幕与音轨、Anime4K、历史记录和诊断日志。
4. 安装与使用：从 Releases 获取 MSIX、证书和快捷方式注意事项。
5. 数据与隐私：媒体索引和缓存不会删除原始视频；无遥测；TMDB 或网络不可用不影响本地扫描和播放。
6. 开发构建：固定 Flutter 3.41.9，列出依赖恢复、测试、分析、Windows Release 和 MSIX 命令。
7. 项目结构：只列出理解主要模块所需的目录。
8. 开源来源与致谢：在文档末尾用简短段落说明播放器 UI 和交互逻辑的 Kazumi 来源，不把它作为看影音的产品定位。
9. 许可证与第三方组件：GPL-3.0、media-kit、Anime4K、Mi Sans、TMDB 和 OpenList。

## 内容边界

- README 是看影音的独立项目文档，不保留或改写旧 README 的产品介绍、功能列表和章节结构。
- 只介绍当前 Windows 项目实际提供的功能，不加入其他平台和旧在线功能。
- 下载入口只指向当前看影音仓库的 Windows MSIX 发布页。
- 当前新图标作为看影音品牌资源展示，不沿用旧图标授权说明。
- Kazumi 仅作为播放器 UI 和交互逻辑的开源来源在末尾注明，以履行来源和许可证说明，不削弱看影音的独立项目定位。

## 约束

- 不加入未经源码或项目配置验证的功能。
- 不在 README 中写入证书密码、API Key 或其他凭据。
- 不把 OpenList 描述为在线内容搜索；它是用户自有媒体数据源。
- 不隐藏 Kazumi 派生关系，保留 GPL-3.0 及必要来源说明。
- 构建命令使用项目固定 SDK 路径和现有 MSIX 流程。

## 验收标准

- README 从看影音自身定位出发，正文不依赖旧项目语境也能完整成立。
- README 中不出现“就看”、旧在线功能、旧下载地址或旧图标授权内容。
- 应用名、包名、Windows 标识和当前版本与项目配置一致。
- 功能描述能在当前页面、服务或设置代码中找到对应实现。
- 看影音独立项目定位清晰，文末 Kazumi 来源、GPL-3.0 和关键第三方组件说明完整且克制。
- Markdown 标题、链接和代码块结构清晰，无占位文本。
- 相关文档测试、`flutter test` 和 `flutter analyze` 通过。
