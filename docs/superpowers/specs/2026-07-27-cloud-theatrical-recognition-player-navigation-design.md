# 网盘剧场版识别、海报缓存与播放防重设计

## 背景

夸克、百度和 OpenList 来源中的作品目录可能同时包含连续剧正片、剧场版、OVA、特别电影和同一影片的不同发布版本。现有媒体树能保存独立视频，但部分没有季集号的视频仍可能继承正剧身份，导致多个剧场版被合并到正剧选集或共用一次电视剧刮削。

当前网盘资源页在解析播放地址后直接压入 `/video/`。海报卡可在解析期间被连续点击；多个异步请求完成后会重复压入播放页。播放页共享同一播放控制器，上层页面退出并释放控制器后，下面残留的播放页会停在静止画面，表现为播放器卡死。

本次将两项改动合并为 2.1.58：剧场版按电影作品独立识别与刮削，同时为所有网盘提供方共用的播放入口增加防重导航。

## 目标

- 正剧连续分集继续按作品和季度聚合。
- 剧场版、OVA、特别电影及其他没有连续季集证据的长视频按独立电影作品识别。
- 不同电影分别刮削并显示独立海报卡。
- 同一电影的 4K、1080P、字幕、配音、剪辑版等发布版本归入同一电影卡，保留全部真实文件。
- 电影海报以稳定作品身份缓存；重新扫描不因远程路径显示细节变化而重复下载。
- 夸克、百度和 OpenList 的网盘资源播放解析与导航期间只接受一次播放请求。
- 不修改或删除用户网盘中的文件、目录、字幕或图片。
- TMDB 不可用、无 API Key 或断网时，扫描、分组和播放继续可用。

## 非目标

- 不将正剧、剧场版或不同影片自动移动到新的网盘目录。
- 不依据时长或文件大小删除预告片、样片或疑似重复文件。
- 不跨作品目录合并同名电影。
- 不重做播放器控件、动画、硬件解码、字幕或 Anime4K。
- 不修改本地媒体库的既有分组规则。

## 方案选择

采用“媒体身份判定、电影版本归并、稳定海报缓存、防重播放导航”四层方案。

未采用每个视频文件单独生成海报卡的方案，因为同一电影的多种清晰度会产生重复卡片和重复 TMDB 请求。未采用把剧场版继续挂在正剧选集中的方案，因为它无法满足不同电影分别刮削，也会混淆电视剧季度海报与电影海报。

## 媒体身份判定

### 连续剧证据

只有存在下列可靠证据时，视频才进入电视剧季度和分集聚合：

- 文件名含明确季集号，例如 `S01E03`、`第1季第3集`、`EP03`。
- 视频位于已确认的季度目录中，文件名提供有效集号。
- 同一作品边界内有多个文件形成连续集号集合，且目录或文件名提供一致的作品标题。

年份、分辨率、`4K`、`1080P`、文件序号和电影发布尾号不能单独作为连续剧证据。

### 独立电影证据

在作品目录中，没有可靠连续剧证据的视频进入独立电影候选。名称分析器从文件名和紧邻目录提取：

- 电影标题候选。
- 年份。
- `剧场版`、`Movie`、`The Movie`、`OVA`、`OAD`、`特别篇` 等内容类型标记。
- 分辨率、片源、编码、动态范围、字幕、音轨、语言和剪辑版等发布标签。

`剧场版` 等标记用于支持电影身份，但不是唯一条件。普通独立电影即使名称不含这些标记，也按电影处理。无法可靠提取标题时保留原文件名并进入待确认，不强制绑定到正剧。

### 正剧目录中的电影

剧场版可以位于正剧作品目录或其子目录中，但会建立独立电影身份。正剧作品标题只能作为辅助别名，不能覆盖电影完整标题。例如同一目录中的两个不同剧场版必须生成两个电影候选，而不是按所属正剧合并。

## 电影作品与版本归并

### 作品边界

电影身份键由来源 ID、作品边界路径和规范化电影标题组成。存在已确认 TMDB 电影身份时，在同一作品边界内使用 TMDB ID 稳定归并。不同来源、不同作品目录或不同电影标题保持隔离。

### 版本判断

归并前先从文件名移除不改变电影内容身份的发布标签，例如：

- `2160p`、`1080p`、`BluRay`、`WEB-DL`。
- `H264`、`H265`、`HEVC`、`AV1`、`HDR`、`DV`。
- 国语、日语、双语、内封、内嵌、简繁字幕等音轨和字幕描述。
- 发布组及常见容器扩展名。

清理后标题与年份一致，或已手动确认到同一 TMDB 电影时，视为同一电影的不同版本。导演剪辑版、加长版、重剪版等有效版本保留为可选择版本，不单独删除；版本标签必须显示在选集或版本选择列表中。

不同标题、不同年份，或候选存在冲突时不得自动归并。无法确认时生成独立待确认卡，用户手动匹配后再按确认身份更新分组。

### 展示与播放

每个电影作品显示一张海报卡。单文件电影点击后直接播放；多版本电影打开现有选择弹层，显示全部真实文件及可区分的版本标签。播放请求继续使用原始远程 ID、远程路径和文件名，不使用显示标题反向定位文件。

## TMDB 刮削

- 连续剧作品只搜索电视剧类型，独立电影只搜索电影类型。
- 每个电影作品执行一次 TMDB 搜索和详情请求，不按发布版本重复请求。
- 查询标题优先级为用户手动名称、已确认身份、规范化电影标题、完整文件标题、正剧作品辅助别名。
- 不同电影分别保存匹配状态、中文标题、简介、评分、年份、海报和背景图。
- 用户手动确认同一电影的任意版本后，只传播到同一来源、同一作品边界和同一电影身份的版本。
- 自动匹配冲突、无结果或网络失败时保留原分组和旧匹配，不写入错误身份。

## 海报缓存

电影海报缓存键使用来源 ID、稳定电影身份、TMDB ID 和海报 URL 版本。稳定电影身份优先使用已确认 TMDB ID；未确认时使用作品边界与规范化标题的哈希。

缓存行为：

1. 本地缓存文件存在且可读时直接使用。
2. TMDB 返回相同海报 URL 时不重复下载。
3. 海报 URL 变化时下载新文件，成功后原子替换记录引用。
4. 下载失败时继续使用旧缓存；没有旧缓存时回退网络地址或占位图。
5. 重新扫描只重建派生身份和引用，不清除仍被有效记录使用的海报。
6. 用户清除来源缓存时只删除看影音专属缓存，不影响网盘原始文件。

电影海报回退顺序为：有效本地缓存、TMDB 网络海报、正剧辅助海报（仅在电影自身没有海报时）、应用默认占位图。

## 播放防重导航

### 入口范围

防重逻辑放在 `CloudResourcesPage` 的共用播放入口，因此同时覆盖夸克、百度和 OpenList，不在各提供方客户端重复实现。

### 状态与流程

页面持有一个 `CloudPlaybackNavigationCoordinator`：

1. 用户选择视频时调用 `tryBegin()` 获取请求代次；繁忙时直接忽略后续点击。
2. 构造播放列表并解析首个播放地址。
3. 异步步骤完成后检查页面仍挂载且请求代次仍为当前值。
4. 只允许当前请求压入一次 `/video/`。
5. 解析失败、页面销毁或导航未发生时释放导航锁，允许重试。
6. 成功压入播放页后结束当前入口请求；下一次播放必须在用户回到资源页并重新操作后开始。

测试注入的 `onPlayRequest` 回调也经过同一防重协调，确保页面测试和生产行为一致。

### 播放控制器边界

本轮不改变播放器控制器的核心生命周期。通过禁止重复压入播放页，保证同一用户操作只存在一个活动播放页，避免一个页面退出时释放另一个页面仍在引用的控制器。

## 并发与错误处理

- 来源切换或页面销毁后，旧播放解析结果不得导航。
- 播放解析失败时显示现有失败提示并释放锁，不记录 Cookie、播放直链或请求头。
- 用户重复点击不会重复解析、重复建立本地中继或重复压入页面。
- 单个电影识别冲突不影响其他电影和正剧扫描。
- 单张海报下载失败不影响媒体卡、版本列表或播放。
- TMDB 服务失败不改变已经确认的身份和有效缓存。

## 数据兼容与迁移

- 提升网盘媒体识别规则版本，使现有来源在远程目录未变化时也重新计算电影身份。
- 保留现有文件级远程 ID、路径、字幕关联和已确认 TMDB 记录。
- 旧记录在同一作品边界内具有相同 TMDB 电影 ID 时归入同一电影；冲突 ID 保持分离并标记待确认。
- 旧海报缓存只有在 TMDB ID 和 URL 能确认归属时复用，不能把正剧海报错误绑定为电影权威海报。
- 迁移和重新扫描只修改看影音派生索引及缓存引用。

## 测试设计

### 识别与分组

- 同一正剧目录中的连续分集仍聚合为季度卡。
- 两个名称不同的剧场版生成两张独立电影卡，并分别产生电影 TMDB 查询。
- 同一电影的 4K、1080P 和不同字幕版本归入一张电影卡，保留三个可播放文件。
- 同名但年份不同的电影不自动合并。
- 同名电影位于不同作品目录或不同来源时保持隔离。
- `OVA`、`OAD`、`特别篇` 和普通独立电影在没有连续季集证据时按电影处理。
- `S01E01`、纯季度目录和连续集号矩阵保持现有电视剧行为。
- 无法判断的文件进入待确认且仍可播放。

### TMDB 与缓存

- 不同电影分别请求电影搜索和详情。
- 同一电影多版本只请求一次详情。
- 已确认 TMDB ID 能稳定复用电影海报缓存。
- 相同 URL 不重复下载，URL 变化时更新缓存。
- 下载失败保留旧缓存，没有缓存时按既定顺序回退。
- 重新扫描和持久化往返不丢失电影身份、版本列表与海报引用。

### 播放防重

- 第一次播放请求获得导航资格，繁忙期间第二次请求被忽略。
- 连续点击同一海报只调用一次解析并压入一次播放页。
- 来源切换或页面销毁后的旧请求不导航。
- 解析失败后可以再次点击重试。
- 成功返回资源页后可以播放另一部影片。
- 夸克、百度和 OpenList 请求均经过相同入口逻辑。

### 回归与交付

- 网盘正剧识别、季度海报、字幕关联、版本选择和本地中继播放测试继续通过。
- 本地媒体库与播放器既有测试继续通过。
- `flutter test` 通过。
- `flutter analyze` 无错误。
- Windows Release 构建通过。
- MSIX 清单版本为 `2.1.58.0`，安装包文件名为 `看影音-2.1.58.msix` 并复制到当前用户桌面。

## 版本与用户文案

`pubspec.yaml` 的 `version` 与 `msix_config.msix_version` 同步升级到 2.1.58。`RELEASE_NOTES.md` 和 `lib/utils/version_history.dart` 使用面向普通用户的文案说明：网盘剧场版可作为独立电影识别，同片不同版本会合并展示，海报缓存更稳定，并修复连续点击网盘视频后播放器可能卡住的问题。

## 验收标准

在夸克、百度和 OpenList 的多选媒体目录中，正剧连续分集维持季度卡；不同剧场版分别显示电影海报并独立刮削；同一电影的多个发布版本只显示一张卡且全部可播放。连续快速点击任意网盘影片只进入一个播放页，退出后能正常返回资源页并继续播放其他影片。断网或 TMDB 不可用时，已扫描影片仍能分组和播放，应用不修改用户网盘中的任何原始文件。
