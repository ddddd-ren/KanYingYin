# TMDB 名称清理与网盘资源性能优化设计

本次测试版统一清理本地和网盘资源的 TMDB 搜索词，并消除网盘资源页在载入几百个资源和执行手动 TMDB 刮削时的重复全量计算。改动不修改用户的本地或网盘原始文件。

## 目标和范围

本次交付包含两个相互独立、在同一测试版发布的改动：

- 本地与网盘 TMDB 搜索词使用同一套发布标签清理规则
- 网盘资源页缓存目录树和海报集合，避免页面通知触发重复全量计算
- 网盘手动 TMDB 搜索和应用候选时复用缓存结果
- 保持播放器、媒体扫描、目录浏览、海报墙布局和原始文件不变

本次不解析或持久化新的媒体规格，不重命名文件，不增加分页，也不把计算迁移到后台 Isolate。

## 已确认的性能根因

`CloudResourcesController.visibleIndexedItems` 遍历每个索引项时访问 `_directoryScopeTree`。现有 getter 每次访问都会使用全部索引路径重建目录树，因此一次过滤会执行多次完整目录树构建，资源数量增加后复杂度接近 O(n²)。`collection` 随后继续执行资源分组和排序。

进入网盘资源页会立即读取 `collection`。手动 TMDB 搜索会在任务开始和结束时发送状态通知，应用候选时还会发送资料更新通知。页面监听任何通知后都会整体重建，并再次读取 `collection`。因此，首次进入页面和手动刮削都受到同一重复计算问题影响。

## TMDB 搜索词清理

新增职责单一的 TMDB 资源名称清洗器。本地 `TmdbScrapePolicy` 和网盘 `CloudMediaNameParser` 复用该清洗器，季集、年份和媒体类型识别继续由各自现有逻辑负责。

清洗器识别以下发布信息：

- 视频编码：`x264`、`x265`、`H.264`、`H.265`、`AVC`、`HEVC`、`AV1`、`VP9`、`VC-1`、`MPEG-2`、`XviD`、`DivX`
- 片源与分辨率：`WEB-DL`、`WEBRip`、`BluRay`、`BDRip`、`REMUX`、`HDTV`、`DVDRip`、`2160p`、`1080p`、`720p`、`4K`、`8K`、`UHD`
- 动态范围：`HDR`、`HDR10`、`HDR10+`、`Dolby Vision`、`DV`、`HLG`、`SDR`
- 音频编码：`AAC`、`AC3`、`EAC3`、`DD`、`DD+`、`DDP`、`DTS`、`DTS-HD MA`、`TrueHD`、`Atmos`、`FLAC`、`LPCM`、`PCM`、`Opus`、`Vorbis`、`WMA`、`APE`、`ALAC`
- 声道信息：与音频标签相邻或组合出现的 `2.0`、`5.1`、`7.1`
- 媒体扩展名：项目支持的常见视频和音频扩展名，仅在资源名称末尾清除

规则忽略大小写，并支持点、空格、下划线和连字符分隔形式。清洗后统一合并空白并清除首尾分隔符。方括号或中文方括号中的内容只有包含已知发布标签时才整体清除，`[REC]` 等正式标题保持不变。

文件扩展名只在名称末尾匹配。规则不使用任意短词或未知尾缀推断，避免误删正式片名。原有年份、季度和集号继续参与结构化识别，不会作为新增发布标签处理。

## 网盘资源派生结果缓存

`CloudResourcesController` 保存已构建的目录范围树，并在来源或媒体索引变化后重建。资源过滤循环直接复用该实例，不再为每个资源重建目录树。

控制器同时缓存当前 `CloudResourceCollection`。以下数据变化时使集合缓存失效：

- 选择或重新加载网盘来源
- 媒体索引、作品树或资源列表变化
- 当前目录范围或搜索词变化
- 隐藏视频记录变化
- TMDB 记录、作品记录或自定义标题变化

扫描目录计数、当前扫描路径、单项 TMDB 刮削中的加载标识等瞬时状态只触发界面通知，不使目录树或资源集合失效。海报卡仍能显示加载遮罩和扫描进度，但不会重新过滤、分组或排序全部资源。

缓存采用惰性计算。首次读取时生成结果，后续读取返回同一结果，直到相关数据变化。控制器继续作为派生状态的唯一入口，页面无需保存第二份资源数据。

## 数据流

进入网盘资源页时，控制器先读取已有快照并重建一次目录树。页面首次读取集合时，控制器按当前目录和搜索词生成一次海报集合。扫描进度通知只刷新进度文本。扫描结束并载入新快照后，控制器使两个缓存失效，下次页面读取时生成新结果。

网盘手动 TMDB 搜索开始后，协调器更新目标卡片的加载状态。页面重建时直接读取缓存集合。用户应用候选后，TMDB 记录发生变化，控制器只使集合缓存失效，保留目录树缓存，并在下一次读取时更新对应展示资料。

本地与网盘生成 TMDB 查询前，先完成各自的季集和年份识别，再调用统一清洗器删除发布标签。清洗结果为空时沿用现有回退行为，不阻断本地扫描、网盘浏览或播放。

## 错误处理和兼容性

TMDB 无 API Key、断网、限流或返回异常时继续使用现有错误提示。缓存不保存网络请求结果，不改变失败重试策略。

目录树和集合缓存只保存当前控制器生命周期内的派生对象，不写入磁盘。切换来源或重新载入快照时清除旧缓存，避免显示其他来源的数据。删除索引、缓存或隐藏记录的操作仍不得删除用户原始视频文件。

## 测试策略

测试遵循先失败、后实现的顺序：

- 为统一清洗器添加表格化测试，覆盖视频编码、片源、HDR、音频编码、声道和媒体扩展名
- 验证本地与网盘对同一资源名生成一致的 TMDB 搜索词
- 验证 `[REC]`、数字片名、季集号和未知括号标题不会被误删
- 使用几百个模拟索引项验证一次集合计算只构建一次目录树
- 验证重复读取集合直接返回缓存结果
- 验证扫描进度和 TMDB 加载状态通知不会重新分组资源
- 验证搜索词、目录范围、隐藏记录、索引和 TMDB 资料变化会正确使缓存失效
- 保留现有页面测试，确认手动刮削遮罩、候选对话框、海报墙和目录浏览行为不变

验收执行全量 `flutter test`、`flutter analyze` 和 Windows Release 构建。完成后生成 MSIX，读取包内 `AppxManifest.xml` 核对标识和版本，并把安装包复制到桌面。
