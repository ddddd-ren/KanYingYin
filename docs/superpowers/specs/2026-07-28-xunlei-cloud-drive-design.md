# 迅雷网盘原生接入与 OpenList 快捷入口设计

## 背景

看影音目前原生支持夸克和百度网盘，并支持通过 OpenList 访问个人媒体。网盘资源页只能直接新增夸克和百度来源，OpenList 虽已有完整编辑、目录选择和扫描能力，但缺少该页面的快捷入口。

本次新增迅雷网盘原生来源，覆盖用户个人网盘的目录选择、媒体扫描、TMDB 刮削和原画播放。同时补齐网盘资源页的 OpenList 新增入口。迅雷个人云盘没有可确认的公开文件 API 文档，因此实现会参考现有夸克分层和 OpenList 的迅雷协议实现，并在产品中明确标记为测试能力。协议变化时必须明确报错，不能影响本地媒体库和其他网盘来源。

参考资料：

- [迅雷开放平台](https://open.xunlei.com/)
- [OpenList 迅雷驱动](https://github.com/OpenListTeam/OpenList/tree/main/drivers/thunder)

## 目标

- 新增原生迅雷网盘来源类型。
- 支持账号、邮箱或手机号加密码完成首次登录。
- 登录成功后只持久化 Refresh Token、Device ID、用户标识和令牌过期信息，账号密码不落盘。
- 支持系统浏览器完成迅雷要求的设备或短信验证。
- 支持选择一个或多个迅雷媒体根目录。
- 复用现有网盘索引、字幕匹配、TMDB、海报墙、隐藏资源和播放界面。
- 使用迅雷原始文件地址进行可取消的 Range 分段播放，不自动降级到迅雷转码视频。
- 在网盘资源页增加 OpenList 快捷入口，复用现有 OpenList 编辑页。

## 非目标

- 不提供迅雷分享链接转存。
- 不提供磁力链接、离线下载或任务管理。
- 不提供上传、删除、移动、复制、改名等远程写操作。
- 不提供公共在线影视搜索。
- 不嵌入 WebView，不解析网页视频。
- 不自动使用迅雷转码视频替代原始文件。
- 不改变正式版 `1.0.2`；首次交付只更新测试版。

## 总体架构

迅雷沿用现有 `CloudDriveClient` 和网盘媒体索引边界，不复制 TMDB 或海报墙业务。

```text
迅雷来源编辑页
  -> XunleiAuthorizationController
  -> XunleiCredentialStore（Windows 安全存储）
  -> XunleiApiClient
  -> XunleiDriveClient
  -> CloudMediaIndexer / TMDB / 海报墙
  -> CloudPlaybackResolver
  -> XunleiRangeRemoteReader
  -> 现有播放器
```

新增 `CloudSourceType.xunlei`，并在来源仓储、序列化、注册表、设置路由、网盘资源页、媒体库筛选和播放解析器中完整处理该类型。旧来源数据保持兼容，未知类型仍按现有安全策略拒绝或隔离。

## 组件设计

### 迅雷凭据模型与安全存储

持久化字段仅包括：

- Refresh Token。
- Device ID。
- 迅雷用户 ID 和用于展示的脱敏账号信息。
- Refresh Token 或会话的已知过期时间。
- 协议确实要求跨请求保存时的 Captcha Token；过期后覆盖。

Access Token 仅保存在客户端实例内存中。账号密码、临时 Credit Key、验证网址和原画地址不得持久化。凭据使用项目现有 Windows 安全存储，并随来源删除一起清理。诊断导出和日志扫描测试必须拒绝上述敏感值。

### 登录与设备验证

`XunleiAuthorizationController` 负责以下状态：空闲、登录中、需要验证、验证重试中、成功和失败。

1. 用户输入账号和密码。
2. 客户端生成稳定的随机 Device ID，并请求登录。
3. 登录成功后写入 Refresh Token 等允许持久化的字段，立即清空密码和控制器中的账号原文。
4. 如果迅雷返回验证网址和临时 Credit Key，控制器进入“需要验证”状态。
5. 应用调用系统默认浏览器打开迅雷返回的 HTTPS 验证网址。
6. 用户完成验证后回到应用点击“验证完成”，控制器使用内存中的 Credit Key 重试。
7. 成功后清除 Credit Key；取消、超时或失败也必须清除密码、Credit Key 和验证网址。

验证网址只允许 `https`，主机必须属于显式维护的迅雷域名集合。应用不注册自定义网页回调，不嵌入 WebView。

### 迅雷 API 客户端

`XunleiApiClient` 只暴露本功能需要的只读操作：

- 登录和验证后重试。
- Refresh Token 换取 Access Token。
- 查询当前用户以验证会话。
- 按父目录 ID 和分页令牌读取文件列表。
- 按文件 ID 获取最新文件详情与原始下载地址。

客户端统一配置连接、发送和接收超时，接受取消信号。错误映射到现有网盘错误分类：鉴权、需要验证、限流、权限、未找到、网络、协议不兼容和未知错误。响应解析使用强类型模型；数值字符串、缺失名称、非法时间、未知文件类型和重复分页令牌都要安全处理。

协议常量集中在迅雷模块内部，不散落到界面或通用网盘代码。不得把账号、Token、验证参数、请求或响应正文写入异常文本和日志。

### 目录与扫描

`XunleiDriveClient` 将迅雷目录和文件转换为 `CloudFileEntry`：

- 迅雷文件 ID 作为稳定 ID。
- 根据遍历上下文构建规范化远程路径。
- 目录与文件严格区分。
- 文件大小和修改时间解析失败时采用安全默认值，不把目录误判为文件。
- 分页结果按文件 ID 去重；重复页在有限次数内终止并报告协议不兼容。

迅雷目录选择页复用统一网盘选择交互，支持地址栏、进入目录、多选当前目录和清除选择。保存来源后，现有 `CloudMediaIndexer` 负责递归、视频筛选、字幕匹配、缓存、TMDB 和作品归并。单个目录失败时继续其他目录并报告失败路径；取消扫描时保留上次完整索引。

### 原画播放

`XunleiRangeRemoteReader` 和播放器解析器遵循以下规则：

- 播放开始前按文件 ID 获取新的原始文件地址和必要请求头。
- 只接受 HTTPS 地址，并沿用项目现有的重定向安全策略，拒绝回环、私网和链路本地目标。
- 严格校验 `206`、`Content-Range` 和响应长度。
- 如果探测请求合法返回完整 `200`，按现有顺序流策略处理，避免重复下载。
- 遇到 `401` 或 `403` 时，只刷新一次令牌并重新获取一次原始地址。
- 链接刷新失败或迅雷只返回转码地址时，明确提示原画地址不可用，不自动降低画质。
- 关闭读取器或取消播放必须终止等待中的网络请求。

播放器控件、字幕、选集、硬件解码、4K 零拷贝和 Anime4K 行为保持不变。

## 界面与入口

### 迅雷来源编辑页

页面与百度、夸克来源编辑页保持一致的表单与反馈风格，包含来源名称、账号、密码、登录按钮、验证状态、媒体目录和保存按钮。

- 密码框不回填；编辑现有来源时不显示 Refresh Token。
- 登录成功后才允许选择目录。
- 需要设备验证时显示说明、“打开验证页面”“验证完成”和“取消验证”。
- 保存后返回来源 ID，网盘资源页刷新并选中新来源。
- 重新登录只在成功后替换旧凭据；失败时保留原来源和可用凭据。

### 网盘资源页

顶部“添加网盘”菜单增加：

- 添加迅雷网盘。
- 添加 OpenList。

空状态增加迅雷和 OpenList 入口，并保留夸克、百度入口。OpenList 直接进入现有 `/settings/cloud-sources/openlist/edit`；迅雷进入新增的 `/settings/cloud-sources/xunlei/edit`。四种来源保存后使用同一刷新与选中流程。

当按钮较多时使用可换行布局，不能造成小窗口横向溢出。来源管理页也增加迅雷新增、编辑和类型标签。

## 错误处理与兼容性

- 无网、超时或迅雷服务不可用：保留旧索引并允许本地和其他网盘继续使用。
- Refresh Token 失效：来源显示“需要重新登录”，不尝试已清除的密码。
- 设备验证失败或过期：允许重新发起登录，不保存临时验证数据。
- 单目录读取失败：继续其他目录，保留失败目录的旧缓存后代。
- 原画地址过期：仅执行一次令牌和地址刷新。
- 协议响应变化：返回脱敏的“不兼容”错误，不能崩溃或写入错误索引。
- 旧版本序列化数据：已有 OpenList、夸克和百度来源正常读取，不进行破坏性迁移。

## 风险说明

迅雷个人云盘接入依赖非公开客户端协议，接口、签名算法、验证码流程和客户端标识可能变化。实现必须将这些变化限制在迅雷模块内，并用协议不兼容错误隔离。不得宣称这是迅雷官方开放 API，也不得通过降低 TLS、安全重定向或凭据保护要求来维持可用性。
