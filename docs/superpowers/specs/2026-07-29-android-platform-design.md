# 看影音 Android 平台设计

日期：2026-07-29

状态：用户已确认方案 A

## 背景

看影音当前是仅包含 Windows 平台工程的 Flutter 应用，源码版本为 `2.1.82+20182`，Windows 包标识为 `com.kanyingyin.player`。项目已经具备本地媒体库、个人网盘、TMDB 元数据、字幕、音轨、选集、硬件解码、Anime4K、后台播放和播放器诊断能力，但入口、应用外壳、本地目录访问及部分播放器交互已经收敛为 Windows 专属实现。

仓库历史中没有可直接恢复的 `android/` 平台目录。2026 年 7 月 24 日的 Windows 专属清理还删除了移动端渲染器设置、系统画中画、移动端亮度和音量分支及 Android 图标。因此 Android 支持必须以当前业务代码为基础重新建立，不能通过简单回滚完成。

## 目标

1. 在同一 Flutter 工程中增加可维护的 Android 正式平台，同时保留 Windows 正式平台。
2. Android 支持本地与个人网盘媒体库、TMDB 元数据、视频播放、字幕、音轨、选集、进度、硬件解码、后台播放、画中画、截图和外部播放器。
3. Windows 与 Android 共用媒体、网盘、TMDB、缓存、凭据和播放器领域逻辑，仅在操作系统能力边界处使用不同实现。
4. Android 本地媒体使用系统存储访问框架取得用户明确授权，不申请“所有文件访问”权限。
5. 桌面托盘、窗口控制、快捷方式和桌面画中画继续只在 Windows 初始化，Android 启动过程不得调用桌面插件。
6. 生成可安装的签名 APK 和用于应用商店分发的签名 AAB，并继续保证 Windows Release 与 MSIX 可交付。
7. 保持现有数据安全约束：删除媒体源、索引或缓存不得删除原始视频；TMDB 不可用时扫描和播放仍可使用。

## 非目标

- 不新增公共在线影视搜索、插件规则、WebView 视频解析或在线评论。
- 不用 Android 的高风险“管理所有文件”权限规避存储访问框架。
- 不为了 Android 重写现有网盘协议、TMDB 匹配或媒体领域模型。
- 不改变 Windows 播放器现有控件层级、动画时长、动画曲线和交互行为。
- 不在仓库中提交发布密钥、密钥密码、网盘令牌、TMDB Key 或其他凭据。

## 方案选择

采用单工程、共享业务、平台能力分层方案。

未采用独立 Android 页面树，因为它会复制导航、设置和媒体库状态。未采用独立 Android 应用包，因为它会让网盘、TMDB、播放器和数据迁移形成两套实现。平台分层只隔离操作系统能力，业务能力继续复用当前 Flutter Modular、MobX 和服务层。

## 总体架构

应用划分为三层：

1. 共享业务层：媒体索引、网盘来源、TMDB、播放会话、字幕、缓存、日志与设置。
2. 平台能力层：应用外壳、窗口与系统界面、本地媒体访问、画中画、截图保存、外部播放器和系统显示能力。
3. 平台工程层：Windows Runner/MSIX 与 Android Gradle/Kotlin/Manifest/签名配置。

共享业务代码只依赖平台能力接口，不直接判断 Windows 或 Android。平台选择集中在应用启动和依赖装配处，避免 `Platform.isWindows` 与 `Platform.isAndroid` 分散到业务模块。

## 平台能力边界

### 应用外壳

建立统一应用外壳接口，至少暴露初始化、监听、关闭请求、全屏、系统亮度同步和销毁能力。

- Windows 实现继续封装 `window_manager`、`tray_manager`、关闭确认、最小化至托盘和系统标题栏。
- Android 实现不创建托盘或桌面窗口监听器，关闭行为交给系统返回栈；进入播放器时使用系统 UI 沉浸模式。
- 桌面窗口按钮、拖动区域和系统标题栏只在平台能力声明支持时构建。

### 画中画

- Windows 保留当前通过窗口置顶、比例和尺寸实现的桌面画中画。
- Android 使用原生 `PictureInPictureParams`，由 Kotlin 平台通道接收视频宽高比和进入请求。
- Android 自动进入画中画作为显式设置，默认关闭；用户主动点击画中画按钮始终可用。
- 不支持画中画或系统拒绝时继续播放并显示普通提示，不终止播放会话。

### 系统显示与音频

- Android 播放页进入沉浸式全屏，退出播放器时恢复系统栏和方向策略。
- Android 音量操作使用系统媒体音量，亮度手势只修改当前 Activity 窗口亮度。
- 使用现有 `audio_service` 与 `audio_session` 提供后台播放通知、媒体按钮、耳机拔出暂停和音频焦点。
- Windows 继续使用现有音频服务路径，不因 Android 接入改变行为。

### 截图与外部播放器

- Windows 保留文件保存对话框。
- Android 截图写入 MediaStore 的图片集合，并在成功后显示保存结果；写入失败不影响播放器。
- Android 外部播放器使用带 MIME 类型的系统 Intent；带鉴权请求头的网盘播放继续拒绝外部唤起，避免凭据泄漏。

## Android 本地媒体访问

### 授权模型

Android 使用存储访问框架的目录树选择器。用户选择目录后，原生层调用持久 URI 授权，应用只访问用户授予的目录及其后代。

不请求 `MANAGE_EXTERNAL_STORAGE`。在 Android 13 及以上，应用也不依赖全库 `READ_MEDIA_VIDEO` 完成用户选定目录扫描；若后续增加“设备全部视频”入口，应作为独立功能设计。

### 数据模型

当前本地媒体索引以 Windows 文件路径为主。新增强类型媒体位置模型，区分：

- Windows 文件系统路径。
- Android 文档 URI。

模型保存稳定标识、显示名称、父级关系、大小、修改时间和可选 MIME 类型。现有 Windows 索引继续读取，不批量改写用户数据。Android 新索引写入 URI，不把 URI 伪装成本地文件路径。

### 扫描与读取

- Windows 扫描器继续使用 `Directory` 与 `File`。
- Android 通过 Kotlin 平台通道枚举 `DocumentsContract` 子项，Dart 层接收强类型目录项并复用扩展名、剧集识别、TMDB 和分组逻辑。
- 扫描不得把完整视频复制到应用缓存。
- 播放器直接打开可读取的 `content://` URI；若底层播放器不能读取特定提供方 URI，使用受控文件描述符桥接，不默认复制整个视频。
- 字幕、封面和元数据读取通过媒体位置接口完成；写入视频同目录的功能在没有写权限时回退到应用专属目录并明确提示。

### 授权失效

启动或刷新时验证持久授权。授权失效后保留索引和 TMDB 资料，标记来源不可访问并引导用户重新授权；不得删除原始文件或静默清空整个媒体库。

## 播放器设计

### Android 解码与渲染

Android 使用 `media_kit` 的 Android 原生库和 MediaCodec 硬件解码。设置提供自动、MediaCodec 嵌入式和 GPU 渲染等实际可用选项，默认选择兼容性优先的自动模式。

Windows 的 `d3d11va`、`d3d11va-copy` 等解码器不得出现在 Android 设置。Android 的渲染器和解码器选择不得写入 Windows 使用的设置键，避免跨平台配置污染。

### Anime4K

- Android 仅在当前渲染器支持 GLSL 且现有自适应策略判断确实需要放大时启用 Anime4K。
- MediaCodec 嵌入式等不支持 GLSL 的渲染路径显示“不支持动画画质增强”，普通播放继续工作。
- Anime4K 加载失败后清空着色器并保持播放，不自动更换用户解码器。
- Windows Anime4K 现有判定、动画和交互保持不变。

### 触控交互

- 保留现有播放器控制层级和动画，Android 根据可用宽度选择紧凑控件组合。
- 单击显示或隐藏控制层，双击左右区域快退或快进，垂直滑动分别调整亮度和音量。
- 鼠标悬停、键盘快捷键和桌面画中画按钮只在对应输入设备与平台能力存在时启用。
- 系统返回键按顺序关闭播放器内浮层、退出全屏、返回媒体库，不能直接导致播放资源泄漏。

## Android 平台工程

使用当前项目固定的 Flutter `3.41.9` 生成 Android 平台目录，并人工核对生成文件，不能覆盖现有 `lib/`、`assets/`、Windows Runner 或项目配置。

Android 配置要求：

- applicationId 与 namespace：`com.kanyingyin.player`。
- 应用显示名：`看影音`。
- `versionName` 和 `versionCode` 分别来自 `pubspec.yaml` 的版本名与构建号。
- 使用当前 Flutter 模板支持的 Kotlin、Gradle、Android Gradle Plugin 和 Java 17。
- `minSdk` 使用当前 Flutter 3.41.9 模板默认的 API 24，`compileSdk` 与 `targetSdk` 使用该 SDK 固定的 API 36；若依赖解析证明某个插件要求更高版本，必须先记录兼容影响并同步修改测试与发布说明。
- 声明联网、前台媒体播放、画中画和必要通知权限；不声明所有文件访问权限。
- Activity 支持画中画、媒体播放所需配置变化和正确的 exported 属性。
- 图标基于现有看影音品牌图生成 Android adaptive icon；启动页使用简洁品牌背景，不引入新品牌。
- Release 构建启用资源压缩和代码压缩，但必须添加播放器、WebView 和音频服务所需保留规则。

## 网盘、WebView 与凭据

- OpenList、夸克、百度和迅雷继续作为用户自有媒体入口。
- 网盘客户端、范围读取、缓存和 TMDB 协调器继续共享。
- `flutter_inappwebview` 在 Android 使用系统 WebView；迅雷验证仍限制初始地址、导航、下载、新窗口和权限请求。
- Android 凭据使用 `flutter_secure_storage` 的平台实现；Windows 已有凭据不迁移到 Android，也不在设备间同步。
- Token、验证码、完整媒体 URI 和签名信息不得进入日志。

## 导航与界面

继续使用 Flutter Modular 与 MobX。媒体库、网盘、设置和播放器路由保持共享，不建立第二套 Android 页面树。

- 顶层布局根据宽度在桌面侧栏和移动端导航之间切换。
- Android 使用安全区域处理状态栏、挖孔屏和系统手势区域。
- 桌面标题栏、窗口拖动区和窗口按钮不占用 Android 布局空间。
- 设置页只展示当前平台支持的选项；Windows 专属与 Android 专属设置通过能力模型控制。
- 所有触控目标满足移动端可操作尺寸，文本缩放后不遮挡主要操作。

## 数据与兼容

- Android 使用看影音专属应用支持、缓存和文档目录。
- Hive typeId、当前模型字段编号和已有 JSON 兼容规则保持稳定。
- 平台专属设置使用不同键；通用主题、字幕偏好、播放进度和网盘配置继续使用共享模型。
- Android 卸载时应用专属数据按系统规则删除，用户通过 SAF 授权的原始媒体不删除。
- 清理来源、索引、缓存或失效 URI 时只删除应用数据，不调用文档提供方删除原始媒体。

## 错误处理

- Android 平台插件初始化失败时，显示可恢复错误页或禁用单项能力，不能因托盘或窗口插件缺失而启动失败。
- Android SDK、NDK、Gradle 或许可证缺失属于构建失败，必须明确报告并修复，不能跳过 Android 产物。
- 网盘或 TMDB 断网时保留已有索引和缓存，本地扫描与已授权媒体播放继续工作。
- SAF 授权失效、播放器不支持 URI、系统拒绝画中画或截图写入失败时均提供面向普通用户的提示，并记录脱敏诊断信息。
- 原生平台通道对方法名、参数和返回值使用明确的数据结构，未知方法返回未实现，异常转换为稳定错误码。

## 测试策略

遵循测试先行。每项行为先增加失败测试，再写最小实现。

### 单元与组件测试

1. 平台能力选择只初始化当前平台实现。
2. Android 启动路径不引用或调用托盘、桌面窗口和 Windows 快捷方式。
3. Windows 启动、关闭、托盘和窗口按钮行为保持现有测试结果。
4. 本地媒体位置能够稳定序列化 Windows 路径与 Android URI，且不会混淆两者。
5. Android 目录项可复用现有扩展名、剧集识别、分组和 TMDB 流程。
6. 授权失效时保留索引并进入重新授权状态。
7. 设置页按能力显示 Android 或 Windows 解码器、画中画和 Anime4K 选项。
8. Android 返回键、全屏和浮层关闭顺序正确。
9. 带鉴权请求头的播放不允许外部播放器泄漏凭据。
10. Android 平台工程清单不包含所有文件访问权限，并包含媒体服务和画中画所需配置。

- `flutter test --no-pub`

- `flutter build apk --release`

- 检查 Windows Release 不包含 Android 专属资产或插件调用路径
- 检查 Android 产物不包含 Windows 证书、快捷方式资源或桌面原生 DLL

### 实机验收

Android 实机至少验证：

- 新安装、冷启动、后台恢复和升级安装。
- 本地目录授权、递归扫描、撤销授权和重新授权。
- OpenList、夸克、百度、迅雷来源配置、浏览、字幕和播放。
- 横竖屏、全屏、字幕、音轨、选集、进度、硬件解码、后台通知、耳机拔出和画中画。
- 支持的 GPU 渲染器下 Anime4K，以及不支持渲染器下的安全禁用。
- 无 TMDB Key、TMDB 不可用和断网场景。
- 删除来源、索引和缓存不会删除原始视频。

Windows 回归至少验证现有播放器动画、全屏、字幕、选集、硬件解码、Anime4K、窗口、托盘和快捷方式。

## 签名与交付

- Android 发布密钥生成到用户受控的本机目录，不提交仓库。
- 仓库只提交不含秘密的签名配置模板；实际密码通过本机未跟踪配置或环境变量传入。
- 交付签名的通用 APK 和 AAB，文件名包含应用名与版本号。
- APK/AAB 复制到当前用户桌面，与 Windows `看影音-版本号.msix` 一起交付。
- 发布前从 Windows 系统查询并记录当前已安装版本；本轮已经确认安装版本为 `2.1.82.0`，实施完成时仍需按发布流程重新核对。
- 进入安装包的修改同步更新 `pubspec.yaml`、`msix_config.msix_version`、`RELEASE_NOTES.md`、`UPDATE_DIALOG_COPY.md`、`README.md` 和 `lib/utils/version_history.dart`。
- 自动提交前检查工作区和关键差异，只提交本轮 Android 工程及共同平台适配。

## 完成标准

只有以下条件全部满足，Android 工程才视为完成：

1. 仓库包含可维护的 Android 平台工程，应用标识和显示名正确。
2. Android 可以安装、启动和正常退出，不调用 Windows 桌面插件。
3. 本地 SAF 媒体库和四类个人网盘均可配置、浏览和播放。
4. TMDB、字幕、音轨、选集、进度、硬件解码、后台播放、系统画中画、截图和外部播放器按设计工作。
5. Anime4K 在支持路径可用，在不支持路径安全禁用且不影响播放。
6. Android 不申请所有文件访问权限，不泄漏密钥、令牌或媒体隐私信息。
7. 完整测试和静态分析通过，签名 APK、签名 AAB、Windows Release 与 MSIX 均构建并验证。
8. Windows 现有功能和播放器交互通过回归验证。
9. 版本、发布说明、安装包清单和桌面交付文件一致。
10. Git 提交只包含本轮相关修改，不包含密钥或构建缓存。
