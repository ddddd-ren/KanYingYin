# TMDB 晚启动代理恢复设计

## 背景

应用启动时会探测 TMDB 直连和常见本机代理。如果应用早于代理软件启动，探测会关闭代理设置，随后创建的 `TmdbClient` 会固定持有直连 Dio。代理稍后启动后，TMDB 对话框中的“重试”仍复用旧 Dio，因此继续超时。

日志已确认该时间线：应用在 10:57 完成失败探测，Clash 在 10:58:54 才启动。当前 `ProxyManager.recoverOnlineResourceProxy()` 已支持共享恢复任务，但 TMDB 请求链路没有调用它。

## 目标

- TMDB 请求遇到可恢复网络异常时，自动重新探测代理。
- 探测成功后按最新网络设置重建 Dio，并重试原请求一次。
- 本地媒体库、网盘单视频、整部作品和设置页 TMDB 测试统一生效。
- 不要求用户退出并重新打开应用。
- 本地扫描和播放不依赖 TMDB，恢复失败时保持现有错误界面。

## 非目标

- 不修改系统代理或启动代理软件。
- 不绕过 TLS 证书校验。
- 不对 API Key 错误、HTTP 401/403/429、数据解析错误或其他业务错误自动重试。
- 不建立无限重试、退避队列或后台轮询。
- 不改动非 TMDB 网络客户端。

## 设计

恢复逻辑集中在 `TmdbClient`。客户端保留 API Key，同时持有可替换的 Dio。默认构造使用现有网络配置工厂创建 Dio；测试可以注入首个 Dio、恢复回调和 Dio 重建工厂。

`search`、详情请求等公开操作通过同一个内部执行器发起。第一次请求成功时直接返回。若捕获到 Dio 的连接错误、连接超时、发送超时或接收超时，则调用一次代理恢复回调。恢复返回 `true` 后，关闭旧 Dio，调用工厂创建读取最新设置的新 Dio，并把原操作重试一次。第二次失败直接向上抛出，不再恢复。

HTTP 状态错误属于已经到达服务器的响应，不触发代理恢复。取消请求、证书错误和未知异常同样不触发。默认恢复回调调用 `ProxyManager.recoverOnlineResourceProxy()`；该方法已有共享 Future，可避免并发失败重复探测。

## 错误处理

- 恢复返回 `false`：保留并抛出第一次网络异常。
- 恢复过程抛出异常：记录脱敏警告，仍抛出第一次网络异常。
- 重建 Dio 后重试失败：抛出第二次异常，交由现有对话框显示失败状态。
- 显式注入 Dio 的调用方默认不启用自动重建，除非同时提供重建工厂，避免测试或特殊调用被隐式替换。

## 测试

采用测试驱动实现，先增加失败测试并确认红灯：

- 第一次连接失败、代理恢复成功时，创建第二个 Dio 并返回重试结果。
- 代理恢复失败时，不创建第二个 Dio且只请求一次。
- HTTP 401、429 等响应错误不调用恢复。
- 第二次网络请求失败时不进行第三次请求。
- 并发共享由现有 `ProxyManager` 契约继续保证。
