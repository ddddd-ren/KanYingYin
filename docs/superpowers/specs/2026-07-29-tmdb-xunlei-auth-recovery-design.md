# TMDB 直连恢复、名称清洗与迅雷授权修复设计

## 背景

当前版本在未开启 VPN 或系统代理时访问 `api.themoviedb.org` 会连接超时，导致 TMDB 元数据刮削不可用；海报域名 `image.tmdb.org` 仍可直接访问。项目过去使用过第三方转发服务和 TMDB 备用域名，但第三方服务已经失效，不应重新引入。

迅雷账号密码登录在验证码初始化阶段返回 `invalid captcha_sign`。核心登录服务仍可访问，因此问题不是账号密码错误，而是项目使用的非公开验证码签名协议已被服务端淘汰。继续猜测或硬编码新签名无法形成稳定、可维护的方案。

本次同时补充用户提供的发布站前缀、语言、片源、季度和合集后缀清洗规则，避免这些内容进入 TMDB 搜索词。

## 目标

1. 未开启 VPN 或代理时，TMDB 元数据刮削可以自动使用可直连的 TMDB 官方备用 API 域名。
2. 保留代理晚于应用启动时的恢复能力，不能因一次连接失败永久锁死 TMDB。
3. 迅雷数据源默认使用 Refresh Token 授权，账号密码登录仅作为兼容入口。
4. 对协议失效、Token 失效、网络异常和限流给出准确提示，不再把所有错误显示为账号密码错误。
5. 清理指定的资源发布前后缀，同时保留片名、年份和季度等有助于匹配的结构化信息。
6. 不读取浏览器凭据，不在普通配置或日志中保存任何敏感信息，不修改或删除用户原始媒体文件。

## 方案选择

### TMDB

采用“官方主端点加官方备用端点”的客户端故障转移：

- 主端点：`https://api.themoviedb.org/3`
- 备用端点：`https://api.tmdb.org/3`
- 图片端点继续使用当前可直连的 `https://image.tmdb.org`

不恢复已经无法解析的 `tmdb.lsmcloud.cc`，也不新增其他第三方代理。与“要求用户始终开启代理”相比，此方案无需额外设置；与“内置公共反向代理”相比，它不引入第三方对 API Key、可用性和隐私的风险。

### 迅雷

采用“Refresh Token 为默认入口、账号密码为兼容入口”的双路径授权：

- Refresh Token 走现有刷新令牌接口，不依赖已经失效的验证码签名。
- 应用为新授权生成并固定复用 32 位十六进制设备 ID。
- 账号密码入口保留，以便协议仍可用的环境继续使用，但不再作为推荐路径。
- 明确不把逆向新版私有签名、自动读取浏览器数据或接入第三方代登录服务列入范围。

## TMDB 端点故障转移

### 端点状态

TMDB 客户端维护当前运行期首选端点，初始为主端点。只有以下连接或服务故障允许切换到备用端点：

- DNS 解析失败；
- 建立连接或接收响应超时；
- TLS/套接字连接异常；
- 主端点返回可重试的 5xx 服务端错误。

401、403 等 API Key 或权限错误不触发端点切换，避免对同一无效配置重复请求。参数错误、资源不存在和其他明确的 4xx 也直接按原错误处理。

主端点故障且备用端点成功后，本次运行中的后续请求优先使用备用端点，避免每次刮削都等待主站超时。应用重启、代理配置变化或代理连接状态恢复时，允许下一次请求重新探测主端点，从而保留代理晚启动恢复能力。两个端点均失败时返回现有可理解的网络错误，本地扫描和播放继续工作。

故障转移只改变 API 请求主机，不改变请求路径、API Key、语言、地区、分页或候选排序逻辑。图片下载维持现状，不把 API 备用主机错误地用于图片 URL。

## TMDB 资源名称清洗

### 处理顺序

名称清洗继续由本地和网盘共用的 TMDB 清洗器负责，按以下顺序执行：

1. 移除已知媒体扩展名。
2. 移除明确的发布站或资源类型前缀。
3. 从原始名称提取年份、`Sxx`、`Season x`、`第x季`、`第x集` 等结构化信息。
4. 移除明确的集数、字幕、音轨、分辨率、片源、编码、HDR/DV、平台和发布组标签。
5. 移除明确的合集、剧场版数量和“全集”尾缀。
6. 合并分隔符与空白，得到 TMDB 搜索词。

年份从搜索词中移除，但写入匹配草稿的年份筛选条件。季号和集号同样从搜索词中移除并写入结构化字段。清洗只影响应用内部识别、搜索和展示，不重命名本地或网盘文件。

### 新增规则

- 发布站括号块：含“高清剧集网”“高清影视之家”“发布”和对应站点域名的 `【...】` 块。
- 资源说明括号块：`[全N集]`、`[高码版]`、`[国语配音+中文字幕]`、`[简繁英字幕]`、`[杜比视界版本]` 等明确发布信息。
- 数量与合集：`全N集`、`全集`、`剧场版N部`、`1-2部合集`。
- 语言与字幕：国语、粤语、日语、简繁英字幕、中字，以及 `Eng`、`Fre`、`Ger`、`Ita`、`Por`、`Spa`、`Cze`、`Hun`、`Pol`、`Rus`、`Tha`、`Tur`、`Chi`、`Jpn` 等发布尾缀。
- 片源与发布规格：`Hami`、`TVING`、`NF`、`HBOMax`、`WEB-DL`、`BluRay`、`Hybrid`、`REMUX`、`PROPER`、`HQ`、分辨率、编码、HDR/DV、音轨及发布组。
- 系列编号前缀：仅在名称开头匹配 `六位数字_（系列）`，例如 `034201_（系列）`。

规则必须有明确边界并优先匹配发布尾部，不能以“删除所有括号内容”或“删除所有数字”的方式实现。正式标题 `[REC]`、纯数字作品名 `1923`、未知括号副标题和片名中的普通数字必须保留。

## 迅雷授权流程

### 数据源编辑界面

迅雷数据源编辑页默认展示“Refresh Token 登录”：

- Token 输入框默认遮挡内容，可临时切换显示；
- 编辑已有来源时不回显已保存 Token，只显示已授权账号状态；
- 用户粘贴 Token 后点击“验证并登录”；
- 未验证成功前禁用目录选择和保存；
- 验证成功后显示账号名称，并允许选择媒体根目录；
- “重新授权”验证新 Token 成功后才替换内存中的待保存凭据；用户取消或验证失败时保留原凭据；
- 账号密码表单折叠在“账号密码兼容登录”区域。

界面不提供自动抓取 Token、读取浏览器数据或访问非官方代登录页面的能力。获取说明只解释粘贴用户本人已有的 Refresh Token，不收集凭据。

### Refresh Token 数据流

1. 校验 Token 非空，生成或复用合法设备 ID。
2. 创建与该设备 ID 绑定的迅雷 API 客户端。
3. 调用刷新接口换取会话。
4. 使用新会话请求账号信息，确认会话确实可用。
5. 以服务端返回的新 Refresh Token 为准，连同设备 ID、必要的验证码令牌、用户 ID 和账号显示名构造凭据。
6. 只有完整流程成功才进入已授权状态；保存数据源时再通过安全凭据存储原子替换旧凭据。

Access Token 只在运行期会话中使用，不写入普通配置。数据源结构继续只保存非敏感的来源名称、根目录引用和扫描状态。

### 账号密码兼容路径

现有账号密码、外部浏览器设备验证和取消流程继续保留。若验证码初始化明确返回 `invalid captcha_sign`，映射为协议不兼容，提示“迅雷登录协议已更新，请改用 Refresh Token”，不能显示成密码错误。明确的密码错误仍提示检查账号密码。

## 错误处理与安全

迅雷错误至少区分：

- Refresh Token 为空、无效或过期；
- 网络不可达和请求超时；
- 请求过于频繁；
- 账号密码错误；
- 设备验证仍需完成；
- 验证码签名协议不兼容；
- 服务端响应结构不兼容。

Refresh Token、设备 ID 和相关凭据仅写入现有 Windows 安全凭据存储。任何 `toString`、异常消息、诊断日志和测试失败输出都不得包含账号、密码、Token、验证码、授权头、请求正文或响应正文。日志只记录功能模块、请求阶段、目标为主/备用端点、HTTP 状态和归一化错误类型。

已保存 Token 过期时保留数据源、目录选择、媒体索引和刮削结果，只把来源标记为需要重新授权。本地媒体和已建立的本地播放能力不受影响。

## 测试设计

### TMDB 客户端

- 主端点连接超时后仅重试一次官方备用端点。
- DNS、TLS、套接字错误和 5xx 可触发切换。
- 401、403、404 和参数错误不触发切换。
- 备用端点成功后成为本次运行期首选。
- 代理配置或连接状态变化后允许重新探测主端点。
- 两个端点失败时返回网络错误，且不会阻塞本地扫描和播放。
- 海报下载仍使用图片端点，并保留现有代理晚启动恢复测试。

### 名称清洗

- 用户提供的每一种前后缀格式均作为参数化测试输入。
- 验证搜索词、年份、季号和媒体类型草稿。
- 验证 `[REC]`、`1923`、普通数字片名和未知括号标题不被误删。
- 验证清洗结果同时用于本地和网盘的自动刮削、手动刮削及重新匹配入口。

### 迅雷

- Refresh Token 成功刷新并获取账号后进入已授权状态。
- 服务端轮换 Refresh Token 时保存新值。
- Token 为空、过期、网络失败、超时和限流映射到对应提示。
- 账号查询失败时不接受半完成凭据。
- 新凭据验证失败或取消时不覆盖旧凭据。
- `invalid captcha_sign` 映射为协议更新提示，真实密码错误保持原提示。
- 默认显示 Refresh Token 登录，兼容表单折叠，授权前目录与保存按钮不可用。
- 日志、对象字符串和错误信息不泄漏任何敏感值。

### 完整回归与交付

- `flutter test` 全部通过。
- `flutter analyze` 无错误。
- Windows Release 构建通过。
- 版本更新为 `2.1.71`，同步 `pubspec.yaml`、MSIX 版本、`RELEASE_NOTES.md` 和版本历史。
- 生成 MSIX，核对清单版本并复制到桌面为 `看影音-2.1.71.msix`。
- 自动测试不使用用户真实 Token；真实迅雷账号联通由用户在本机安装后使用自己的 Token 完成冒烟验证。

## 验收标准

1. 在不开 VPN、不开代理的环境中，主 API 域名不可达时能通过 `api.tmdb.org` 完成中文元数据刮削并正常下载海报。
2. 代理晚启动或代理状态变化后，TMDB 不会停留在不可恢复状态。
3. 用户提供的发布前后缀不会进入搜索词，年份和季号仍能参与匹配。
4. 有效 Refresh Token 可以完成迅雷授权、账号确认、目录浏览和数据源保存。
5. 旧账号密码协议失效时显示准确的协议更新提示。
6. 日志、配置和界面不泄漏任何敏感凭据。
7. 本地扫描、离线播放、已有媒体索引和用户原始文件不因 TMDB 或迅雷失败而受损。

## 非目标

- 不逆向或硬编码迅雷新版私有验证码签名。
- 不自动读取浏览器、迅雷客户端或其他应用中的 Token。
- 不恢复或新增第三方 TMDB 反向代理。
- 不修改、重命名或删除任何本地及网盘原始媒体文件。
- 不在本次变更中重做 TMDB 候选排序、播放器或网盘索引架构。
