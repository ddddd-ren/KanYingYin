# 迅雷应用内设备验证与密码错误提示设计

## 背景

迅雷账号密码兼容登录在部分账号上会返回 `review_panel` 设备验证挑战。服务端给出的短信验证地址存在两层兼容问题：

1. 返回地址可能使用已经下线的 `/xlcaptcha/verifyPhone.html`，实际资源仍部署在历史拼写 `/xlcaptcha/vertifyPhone.html`。
2. `vertifyPhone.html` 不是可独立打开的完整页面，而是默认隐藏的验证子页面。它必须由迅雷官方 `android.html` 容器加载，并通过 `XLJSWebViewBridge` 提供挑战数据、调用 `XlCaptcha.init(...)` 后才会显示。

版本 2.1.72 已修正第一层路径并补齐设备签名，但系统浏览器仍直接打开子页面，因此页面标题为“短信验证”而正文保持空白。本次设计从根本上补齐官方容器与桥接流程。

项目明确不包含公共在线影视搜索和 WebView 视频解析。本次 WebView 仅用于用户本人迅雷账号的设备验证，不能导航或扩展为媒体网页、视频解析或公共内容入口。

## 目标

1. 账号密码兼容登录触发设备验证时，在看影音内显示可交互的迅雷官方短信验证界面。
2. 验证成功后自动关闭验证窗口，并使用服务端返回的新 CreditKey、原设备 ID 和原登录会话继续登录。
3. 迅雷明确返回密码错误时，在密码输入框下显示“迅雷密码错误，请重新输入”，清空密码并恢复输入焦点。
4. 验证窗口只加载受信任的迅雷 HTTPS 页面，不保存挑战参数、密码、Token、Cookie、缓存或浏览历史。
5. WebView2 不可用、页面加载失败、验证取消、超时和协议异常都有明确反馈，不再打开空白系统浏览器页面。
6. 迅雷验证失败不得影响本地媒体库、其他网盘来源、播放器或用户原始文件。

## 方案比较与选择

### 方案一：应用内 WebView2 容器与最小原生桥接（采用）

使用 `flutter_inappwebview` 的 Windows WebView2 实现加载迅雷官方 `android.html`。在页面脚本执行前注入最小 `XLJSWebViewBridge`，只处理“读取本次挑战数据”和“返回验证结果”两类消息。

优点是复用迅雷现有短信、图形验证和风控页面，用户无需打开开发者工具，验证成功后可以自动续登。缺点是增加 Windows WebView2 依赖，需要处理运行时缺失、导航限制和临时浏览数据清理。

稳定版 `flutter_inappwebview 6.1.5` 要求 Dart 3.5、Flutter 3.24，满足项目 Dart 3.11 / Flutter 3.41.9 环境；其 Windows 实现提供文档开始时脚本、JavaScript Handler、导航拦截和无痕设置所需能力。

### 方案二：Dart 直接实现短信验证接口（不采用）

直接调用迅雷短信发送、短信校验和图形验证码接口可以避免 WebView，但这些均为非公开协议，且风控流程会按账号和环境变化。实现需要复制网页端状态机并持续追踪私有接口，容易把真实密码错误、设备验证和协议变化混为一谈。

### 方案三：系统浏览器加手动控制台命令（不采用）

打开 `android.html` 后让用户在浏览器开发者工具中调用 `reviewCb(...)`，可以复用官方页面，但步骤复杂，会把挑战数据暴露在剪贴板和控制台，也无法可靠地把成功结果返回应用。

## 组件边界

### `XunleiVerificationChallenge`

把本次设备验证需要的数据作为强类型、不可变对象保存在内存：

- 官方 Review URL；
- 初始 CreditKey；
- 与兼容登录一致的设备 ID 和设备签名；
- 挑战开始时间。

对象的 `toString()` 只输出脱敏占位，不提供 JSON 持久化。取消、成功、超时和控制器销毁时都必须清除引用。

### `XunleiVerificationBridge`

负责生成页面加载前注入的桥接脚本，并解析 WebView 返回的消息。桥接只支持：

- `nativeGetUserDeviceInfo`：把本次挑战对象交给迅雷页面的回调函数；
- `nativeRecvOperationResult`：接收取消、失败或成功结果；成功结果必须包含非空的新 CreditKey。

所有字符串通过 JSON 编码注入，不能用字符串拼接生成可执行脚本。未知消息、未知回调名、超长消息和结构异常一律拒绝。异常对象和日志只记录归一化类型，不能包含消息正文。

### `XunleiVerificationDialog`

Windows 专用弹窗，保持现有设置页的控件风格、圆角和交互节奏。弹窗包含标题、加载状态、错误状态、重试和取消按钮，以及 WebView 内容区域。

弹窗使用专用临时 WebView2 环境和无痕设置。禁止新窗口、下载、摄像头、麦克风、位置、剪贴板读取和其他权限请求。主框架和子框架只允许 `https://i.xunlei.com`；XHR 与静态资源仅允许迅雷验证页面自身发起，应用不读取响应正文。

关闭弹窗时先停止加载、移除 Handler、清除 Cookie 和缓存、销毁 WebView，再删除专用临时用户数据目录。清理失败只记录归一化诊断，不保留挑战对象，也不阻止用户返回设置页。

### `XunleiAuthorizationController`

控制器继续拥有账号密码和验证生命周期：

- 首次登录遇到挑战时进入 `verificationRequired`；
- UI 打开应用内验证弹窗；
- 验证成功时将新 CreditKey 传回控制器；
- 控制器使用原设备 ID、账号和内存中的密码重新调用核心登录；
- 登录成功后只生成允许持久化的 Refresh Token、设备 ID、Captcha Token、用户 ID 和账号显示名；
- 任何结束路径都清除密码、旧 CreditKey、验证 URL 和开始时间。

## 数据流

1. 用户在“账号密码兼容登录”中输入账号和密码。
2. 核心登录返回 `review_panel`，API 客户端解析并校验官方 HTTPS Review URL。
3. 授权控制器保存临时挑战，设置页打开 `XunleiVerificationDialog`。
4. WebView 在官方页面脚本运行前注册受限桥接，再加载 `https://i.xunlei.com/xlcaptcha/android.html`。
5. 官方容器调用 `nativeGetUserDeviceInfo` 时，桥接把 Review URL、初始 CreditKey、设备 ID 和设备签名交给指定回调。
6. 官方容器加载短信或图形验证子页面，用户在 WebView 内完成验证。
7. 官方容器通过 `nativeRecvOperationResult` 返回结果。成功结果中的新 CreditKey 经强类型解析后返回设置页。
8. 弹窗自动关闭并完成浏览数据清理，控制器使用新 CreditKey 自动继续登录。
9. 账号信息确认成功后进入已授权状态；失败则显示对应错误并清除临时秘密。

## 密码错误提示

API 错误分类新增独立的“密码错误”类型。只有核心账号密码登录接口明确返回密码校验失败的错误码或稳定错误标识时，才映射为该类型。以下情况不得显示密码错误：

- 设备验证挑战；
- `invalid captcha_sign` 等协议变化；
- 网络错误、超时和限流；
- Refresh Token 无效；
- 服务端结构不兼容。

设置页收到明确密码错误后：

1. 在密码输入框下显示“迅雷密码错误，请重新输入”；
2. 清空密码输入框；
3. 把输入焦点恢复到密码框；
4. 保留账号输入，便于用户立即重试；
5. 不把密码、账号或服务端响应正文写入日志。

## 安全与隐私

- 初始地址固定为迅雷官方 `android.html`，不直接打开服务端返回的子页面。
- Review URL 必须是 HTTPS、无用户信息、端口为 443、主机精确等于 `i.xunlei.com`。
- WebView 主框架和子框架导航使用同一白名单；拒绝 `data:`、`file:`、`javascript:`、HTTP、相似恶意域名和外部跳转。
- 桥接只注入本次验证所需字段，不暴露访问令牌、Refresh Token 或 Windows 凭据存储内容。
- 验证内容只在 WebView2 进程内存和 Dart 内存中短暂存在，不写入普通配置、诊断日志、剪贴板或临时 HTML 文件。
- WebView 控制台消息、请求地址和响应正文不转发到应用日志。
- 十分钟超时沿用现有授权策略，过期挑战不能继续使用。

## 错误处理

- WebView2 Runtime 缺失或初始化失败：提示“迅雷验证组件不可用，请安装或修复 Microsoft Edge WebView2 Runtime”。
- 官方容器或子页面加载失败：显示“迅雷验证页面加载失败”，提供重试和取消。
- 主框架或子框架尝试离开白名单：取消导航并显示安全提示。
- 用户关闭或取消：关闭 WebView、清除临时数据，授权状态回到空闲。
- 官方返回取消：按用户取消处理，不显示登录失败。
- 官方返回失败或未知结构：显示“迅雷设备验证失败，请重新登录”，清除挑战。
- 成功结果缺少新 CreditKey：按协议不兼容处理，不能使用旧值冒充成功。
- 续登再次要求验证：停止自动循环，提示重新发起登录，避免无限弹窗。
- 明确密码错误：使用密码框内联提示，不显示设备验证或协议更新文案。

## 测试设计

### 纯 Dart 单元测试

- 桥接脚本使用 JSON 编码安全传递引号、反斜杠和 Unicode，不产生脚本注入。
- 只接受两个受支持的桥接消息和预期回调名。
- 成功、取消、失败、缺少 CreditKey、超长消息和畸形 JSON 均映射正确。
- URL 策略只允许 `i.xunlei.com` HTTPS 页面，拒绝相似域名、用户信息、非 443 端口和非 HTTPS 协议。
- API 客户端区分明确密码错误、设备验证、协议更新、网络、超时和限流。

### 控制器测试

- 验证成功使用新 CreditKey、原设备 ID 和原密码只续登一次。
- 续登成功后清除所有临时秘密，只留下允许持久化的凭据。
- 取消、超时、页面失败、协议异常和再次挑战都清理状态且不生成凭据。
- 明确密码错误设置独立错误类型和用户提示。

### Widget 测试

- 收到挑战时打开应用内验证弹窗，不再调用系统浏览器。
- 加载、重试、取消、成功自动关闭和错误状态均可见且可操作。
- 明确密码错误时密码框显示内联提示、内容清空、账号保留并恢复焦点。
- WebView2 不可用时显示安装或修复提示。
- 弹窗关闭后设置页不再访问已销毁的 WebView 或输入控制器。

### Windows 实机与交付

- 使用虚构数据测试白名单、桥接解析和无痕清理，不调用真实短信接口。
- 使用用户本人账号进行一次真实设备验证冒烟测试，确认短信页面可见、验证成功后自动续登。
- 验证 WebView2 缺失和页面断网的错误提示。
- `flutter test`、`flutter analyze` 和 Windows Release 构建通过。
- 更新到下一版本，同步版本历史和发行说明，生成签名 MSIX 并核对清单版本。

## 验收标准

1. 触发迅雷设备验证后不再打开系统浏览器空白页，而是在应用内显示官方短信或图形验证界面。
2. 验证成功后弹窗自动关闭，应用自动继续登录并允许选择媒体目录。
3. 明确输错密码时，密码框显示准确提示并可立即重新输入。
4. 设备验证、协议变化、网络错误和 Token 失效不会误报为密码错误。
5. 任何日志、普通配置、剪贴板和临时文件都不包含账号、密码、Token、CreditKey、完整验证 URL 或响应正文。
6. 关闭、取消、超时和失败后不存在可继续使用的临时挑战或 WebView 浏览数据。
7. 本地扫描、播放、TMDB 和其他网盘来源不受迅雷验证结果影响。

## 非目标

- 不实现公共网页浏览、在线影视搜索、WebView 视频解析或网页播放器。
- 不自动读取 Chrome、Edge、迅雷客户端或其他应用中的 Cookie、Token 和账号数据。
- 不绕过短信、图形验证码、风控或账号安全验证。
- 不自行实现或猜测迅雷私有短信验证接口。
- 不保存账号密码，不修改或删除本地及网盘原始媒体文件。
