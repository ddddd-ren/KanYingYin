# 刮削资料跨设备迁移设计

## 背景与目标

用户在新设备中仍使用同一批本地视频和个人网盘资源，但重新添加来源并扫描后，需要再次执行 TMDB 刮削。该过程耗时，并且可能丢失已经确认的匹配结果、手动标题和离线图片。

本功能提供一个专用的 `.kyymeta` 便携迁移包。旧设备导出已成功刮削的资料和已缓存图片，新设备在完成媒体来源配置与扫描后导入，直接复用原有 TMDB 结果，不重新访问 TMDB。

首版覆盖：

- 全部本地媒体来源。
- 全部个人网盘来源，包括 OpenList、夸克、百度和迅雷。
- TMDB 中文标题、原始标题、简介、评分、发行日期、媒体类型、匹配来源、匹配规则版本和季集资料。
- 手动显示名称、刮削搜索名称以及标题、简介和海报锁定状态。
- 已缓存的作品海报、背景图和季度海报。

首版不迁移：

- 视频、字幕或其他用户原始文件。
- 本地或网盘媒体索引、目录指纹和播放记录。
- 网盘账号、密码、Cookie、访问令牌和其他凭据。
- TMDB API Key、应用设置和诊断日志。
- 未匹配、匹配失败或仅完成媒体识别但没有 TMDB 资料的记录。

## 用户流程

### 导出

1. 用户打开“设置 → TMDB 刮削”。
2. 用户在“刮削资料迁移”区域点击“导出刮削资料”。
3. 应用收集所有已经成功匹配且包含 TMDB 资料的本地、网盘单资源、网盘整部作品和网盘系列继承规则。
4. 应用收集这些记录引用的可用缓存图片，按内容去重并计算 SHA-256。
5. 用户选择保存位置，应用生成默认名为 `看影音刮削资料-YYYYMMDD.kyymeta` 的迁移包。
6. 应用显示本地记录数、网盘记录数、图片数以及因记录或图片损坏而跳过的数量。

单张图片丢失或不可读时，只跳过该图片，仍导出对应文本资料。单条损坏记录不会阻止其他记录导出。

### 导入

1. 用户先在新设备添加本地媒体目录、登录并配置相同的网盘来源，然后完成扫描。
2. 用户在“刮削资料迁移”区域点击“导入刮削资料”并选择 `.kyymeta` 文件。
3. 应用在临时目录中读取包，校验格式版本、清单结构、文件路径和 SHA-256。
4. 应用生成导入预览，展示自动匹配的来源、需要手动选择的新本地根目录、无法匹配的网盘来源，以及预计覆盖、未找到和可恢复图片数量。
5. 用户为无法自动映射的本地来源选择新根目录。
6. 用户点击“确认导入”后，应用覆盖同一媒体的现有刮削结果。
7. 应用刷新本地与网盘媒体库，并显示已恢复、未匹配、图片缺失和来源未配置的数量。

选择文件和查看预览不会写入任何数据。只有确认导入后才发生修改。

## 迁移包格式

`.kyymeta` 是 ZIP 容器，使用固定 UTF-8 文件名和 JSON 内容：

```text
manifest.json
local.json
cloud.json
images/
  <sha256>.<扩展名>
```

`manifest.json` 至少包含：

- 格式标识 `kanyingyin-scraped-metadata`。
- 整数格式版本，首版为 `1`。
- 导出应用版本和 UTC 导出时间。
- 本地、网盘和图片条目数量。
- 每个包内数据文件和图片的相对路径、字节长度和 SHA-256。

数据文件中的图片只保存包内相对路径，不保存旧设备缓存绝对路径。图片名称以内容 SHA-256 为主体，相同内容只写入一次。

未知的更高格式版本必须拒绝导入，并提示用户更新看影音。低于当前版本的格式由明确的迁移器升级，不能依赖宽松解析静默猜测。

## 本地媒体身份与映射

迁移包不复制本地媒体索引。每条本地刮削记录保存：

- 导出来源标识及原来源根路径，仅用于显示和建立来源映射。
- 媒体相对来源根目录的规范化路径。
- 文件名、文件大小以及现有路径指纹中的可移植部分。
- TMDB 资料、匹配状态、匹配来源、规则版本、手动覆盖和锁定状态。
- 作品、季度和背景图片的包内引用。

导入时先建立“导出来源 → 当前本地来源”映射：

1. 原绝对根路径仍存在且已经配置时自动匹配。
2. 否则使用来源末级目录名、相对媒体路径覆盖率和文件大小进行候选评分。
3. 只有唯一的高置信度候选才自动匹配；歧义来源要求用户选择当前根目录。

来源映射完成后，媒体按规范化相对路径和文件大小精确匹配。路径比较在 Windows 上不区分大小写并统一目录分隔符。文件大小不一致、相对路径不存在或出现多个候选时，记录进入未匹配统计，不能仅按文件名强行套用。

导入只更新当前索引项中的 TMDB 及相关覆盖字段，保留当前设备的媒体位置、父目录、来源位置、字幕、时长、分辨率、文件指纹、索引时间和其他扫描结果。

## 网盘来源身份与映射

迁移包仅保存建立来源映射所需的非凭据描述：

- 网盘类型。
- 来源显示名。
- OpenList 的规范化服务地址；地址中的用户信息、查询参数和片段必须移除。
- 已配置媒体根目录的远程路径和非敏感远程 ID。
- 资源的远程路径、远程 ID、作品根路径和作品身份字段。

导入时只在新设备已经配置且完成扫描的来源中匹配：

1. 网盘类型必须相同。
2. 根目录远程 ID 相同的候选优先。
3. 其次比较规范化根目录路径；OpenList 还需比较规范化服务地址。
4. 只有唯一候选可以自动匹配，歧义或缺少来源时跳过并提示用户先配置来源。

来源映射后，所有记录中的旧 `sourceId` 重写为当前来源 ID。网盘单资源按远程 ID 和规范化远程路径关联；整部作品按当前媒体索引生成的作品身份关联；系列继承规则按规范化父路径和系列名关联。远程 ID 变化时可以使用同一来源内的规范化远程路径回退，但不能跨来源或仅按显示名称匹配。

导入不会创建网盘来源、发起登录、保存凭据或访问 TMDB。

## 图片处理

导出范围是相关刮削记录实际引用且当前可读的缓存图片，包括：

- 作品海报。
- 当前已有独立缓存文件的背景图。
- 电视剧季度海报。

只存在网络 URL、但没有可读缓存文件的图片不会在导出时联网补下载，仍保留 URL 并计入“图片未缓存”提示。

导入时图片先解压到看影音专属临时目录，校验通过后复制到新设备专属刮削缓存目录。记录中的作品、背景和季度图片路径全部重写为新路径。包内引用缺失或校验失败时，不写入无效的旧设备路径；文本资料仍可恢复，并保留原 TMDB 图片 URL 供后续正常加载。

## 覆盖语义与一致性

用户选择的导入策略是“导入包覆盖同一媒体的现有刮削资料”。

覆盖范围仅限：

- TMDB 元数据和季集元数据。
- 刮削状态、匹配来源和规则版本。
- 手动显示名称、刮削搜索名称。
- 标题、简介和海报锁定状态。
- 与导入资料对应的缓存图片路径。

不覆盖当前设备的媒体身份、位置、索引扫描信息、字幕关联、播放记录或来源配置。

确认导入后按以下阶段执行：

1. 将全部图片和待写数据准备到临时区。
2. 再次验证来源映射和当前媒体身份。
3. 记录所有受影响数据的回滚快照。
4. 提交本地记录、网盘单资源记录、网盘整部作品记录和系列继承规则。
5. 将已校验图片移入正式缓存并重写路径。
6. 刷新媒体库。

任一数据提交或图片提交失败时，使用快照恢复本轮修改，并删除本轮已创建的缓存文件。迁移包本身不修改，临时目录在成功、失败和用户取消后都应清理。

## 组件边界

新增组件保持独立职责：

- `ScrapedMetadataArchiveCodec`：编码和解码版本化迁移包，验证结构、路径、大小和哈希。
- `ScrapedMetadataExporter`：从仓库生成可移植记录并收集图片，不负责 UI 或选择文件。
- `ScrapedMetadataImportPlanner`：读取当前来源和索引，生成来源映射、媒体匹配及预览，不写数据。
- `ScrapedMetadataImporter`：执行用户确认后的覆盖、图片落盘和失败回滚。
- `ScrapedMetadataTransferPage`：负责文件选择、映射交互、预览、确认和结果展示。

现有仓库补充最小的批量读取、批量覆盖或替换接口，继续由仓库负责序列化和同步锁。迁移服务不直接读写 Hive 键。

“设置 → TMDB 刮削”页新增“刮削资料迁移”区域，并进入独立迁移页，避免把文件选择、来源映射和进度状态堆入现有凭据设置页面。

## 安全与错误处理

导入器必须：

- 拒绝绝对路径、`..` 路径段、重复归一化路径和符号链接条目。
- 限制包内条目数、单文件大小和总解压大小，先检查声明大小并在流式解压时再次计数。
- JSON 解析使用强类型边界，未知可选字段可忽略，缺少必需字段必须报错。
- 验证清单所列每个文件的实际长度和 SHA-256。
- 不执行包内内容，不将包内路径直接拼接为未验证的磁盘路径。
- 日志只记录数量、格式版本和非敏感错误，不记录网盘凭据或完整远程地址。

首版固定限制：

- 最多 100,000 个数据记录。
- 最多 20,000 张图片。
- 单张图片最多 25 MiB。
- 总解压大小最多 10 GiB。

空间不足、权限不足、格式损坏和版本不兼容都应显示可理解的中文错误，并保证原有媒体及刮削资料可继续使用。

## 测试与验收

单元测试覆盖：

- 包格式往返、UTF-8 中文内容、固定格式版本和哈希校验。
- 导出内容不含凭据、Cookie、令牌、TMDB Key、视频或字幕内容。
- 图片去重、缺失图片跳过和包内路径重写。
- 本地根目录或盘符变化后的自动匹配和手动映射。
- 本地相对路径相同但大小不同时拒绝误配。
- 网盘来源 ID 变化后的类型、根目录和远程身份匹配。
- 网盘来源缺失、歧义和远程 ID 变化时的安全行为。
- 覆盖已有刮削资料，同时保留当前媒体位置和索引字段。
- 数据或图片提交失败后的回滚。
- ZIP 路径穿越、压缩炸弹边界、未知版本、缺失文件和哈希不一致。

组件测试覆盖：

- TMDB 设置页能够进入刮削资料迁移页。
- 导出选择、进度和结果摘要。
- 导入预览、本地来源映射、确认覆盖和取消。
- 网盘未配置提示和最终汇总。

项目级验收：

- 在设备 A 导出同一批本地与网盘资源的已刮削资料。
- 在设备 B 重新配置来源并扫描，其中本地根目录盘符与设备 A 不同。
- 设备 B 在断网且不配置 TMDB Key 的情况下成功导入。
- 已匹配媒体直接恢复标题、简介、评分、海报、背景图和季度资料。
- 目标设备原有同媒体刮削资料被导入包覆盖。
- 无对应媒体和未配置来源不会误写入其他资源。
- 原始视频、字幕和网盘内容无任何修改。
- `flutter test`、`flutter analyze` 和 Windows Release 构建通过。
