# 看影音 2.1.94 测试版风险修复设计

日期：2026-08-01

状态：用户已确认执行

## 背景

当前仓库版本为 `1.0.3+10003`，MSIX 版本为 `1.0.3.0`，但本机同一包标识 `com.kanyingyin.player` 已安装 `2.1.93.0`。Windows 不允许同一包标识以低版本覆盖高版本，因此现有 `1.0.3.0` 包不能完成升级安装。

项目检查还确认了四类风险：Anime4K 着色器准备异常可能阻断应用导航；播放器释放任一步骤抛错后可能保留并复用旧播放器；迅雷客户端标识与凭据以字面量保存在跟踪源码中；Windows 构建使用的 WebView beta 插件在当前 CMake/MSVC 下产生已知开发警告。仓库同时保留 Android 代码，但本轮按用户确认只交付 Windows 测试版。

## 目标

1. 发布可覆盖本机 `2.1.93.0` 的 Windows `2.1.94` 测试版。
2. 着色器目录或资产准备失败时仅禁用 Anime4K，不阻断应用启动、本地扫描和普通播放。
3. 播放器资源释放失败时仍尝试全部释放步骤，立即解除控制器对旧播放器的所有权，禁止复用半释放实例。
4. 从跟踪源码移除迅雷客户端 ID 和客户端凭据字面量，改由测试版构建配置注入；缺少配置时明确禁用迅雷授权，不影响其他媒体能力。
5. 明确本轮为 Windows 测试版，保留 Android 代码但不构建、不安装、不发布 Android 包。
6. 消除本项目可控制的 WebView CMake/MSVC 构建警告，不降级或替换当前 Windows WebView 实现。
7. 完成测试、静态分析、Windows Release、签名 MSIX、清单和签名验证、升级安装验证、桌面交付和 Git 提交。

## 方案比较

### 方案 A：单调测试版本、可选安全构建配置（采用）

- 版本更新为 `2.1.94+20194`，MSIX 为 `2.1.94.0`，版本历史标记为测试版。
- 迅雷构建凭据通过 `--dart-define-from-file` 注入，受保护源文件保存在用户目录，不进入仓库。
- 启动和播放器问题以独立、可测试的容错边界修复。
- Windows WebView 继续固定当前 beta 版本，仅显式选择兼容的 CMake 策略并屏蔽第三方头文件的已知 C4458 警告。

优点是保持包标识和升级链不变，功能不回退，改动可以被自动测试覆盖。缺点是桌面原生程序中的客户端凭据仍可被逆向，因此它只能被视为可轮换的构建配置，不能视为真正机密。

### 方案 B：继续使用 1.0.x 并要求卸载旧测试版（不采用）

这会破坏覆盖升级，可能让用户丢失 MSIX 管理的数据，并违反版本更新前核对已安装版本的项目规则。

### 方案 C：删除迅雷能力或更换 Windows 包标识（不采用）

删除迅雷会造成已有功能回退；更换包标识会形成第二个应用和新的数据迁移问题，均超出本次风险修复目标。

## 版本与平台范围

- Dart/Flutter 版本：`2.1.94+20194`。
- Windows MSIX 版本：`2.1.94.0`。
- Windows 包标识保持 `com.kanyingyin.player`。
- `RELEASE_NOTES.md`、`UPDATE_DIALOG_COPY.md`、`README.md`、`lib/core/app_version.dart` 与 `lib/utils/version_history.dart` 同步更新。
- 当前版本历史条目标记 `isPrerelease: true`，用户文案使用“测试版”。
- Android 工程和现有 Android `1.0.0` 代码保留，但本轮发布说明明确“未构建 APK/AAB、未完成 Android 真机验收”。

## 启动容错设计

将着色器准备结果改为可空目录：

1. `ShadersController` 不再使用可能未初始化的 `late Directory`。
2. 资产清单、应用支持目录或目录创建失败时记录脱敏日志并返回失败结果。
3. `InitPage` 无论着色器准备成功与否都继续快捷方式检查和默认页面导航。
4. 玩家请求 Anime4K 时若目录不可用，进入安全禁用状态并提示该能力当前不可用，普通播放不受影响。

测试以注入的目录和资产读取函数模拟失败，证明失败结果不会抛到启动调用方，并证明未准备目录时不会生成着色器路径。

## 播放器资源释放设计

新增小型资源释放协调器，按顺序执行所有释放步骤并收集失败：

1. `PlayerController` 在任何异步释放前把订阅、播放器和视频控制器引用转移到局部变量并将成员置空。
2. 取消错误订阅、取消调试订阅和释放播放器互不阻断；前一步失败时仍执行后一步。
3. 所有失败统一写入脱敏诊断日志，不在新媒体初始化时复用旧实例。
4. 新媒体初始化只使用新建播放器；释放失败不会被静默吞掉。

测试先构造第一步抛错、后续步骤成功的场景，确认所有步骤均执行且失败被返回；再验证控制器源码不再以 `mediaPlayer ??=` 复用旧实例。

## 迅雷构建配置设计

新增强类型 `XunleiClientConfiguration`：

- 默认值来自 `KANYINGYIN_XUNLEI_CLIENT_ID`、`KANYINGYIN_XUNLEI_CLIENT_SECRET`、`KANYINGYIN_XUNLEI_WEB_CLIENT_ID` 和 `KANYINGYIN_XUNLEI_APP_KEY` 四个 `String.fromEnvironment` 构建参数。
- 配置只暴露 `isConfigured` 和经过校验的 ID/凭据，不提供日志字符串。
- `XunleiRequestPolicy` 使用实例配置；API 客户端全部通过已注入的策略读取，不再引用静态凭据字面量。
- 配置缺失时，授权入口显示“当前构建未配置迅雷授权”，不会发送半配置请求，也不影响已有本地和其他网盘能力。

本机交付脚本从 `%USERPROFILE%\.kanyingyin\signing` 下的 DPAPI `clixml` 文件读取两项值，在临时目录生成仅含 Dart Define 的 JSON，构建完成后在 `finally` 中删除，并清零明文 BSTR。GitHub Release 工作流只从 GitHub Secrets 生成同类临时 JSON；PR 质量构建允许无凭据编译。源码、日志、异常、ZIP 和 MSIX 外部文件清单不得包含明文配置。

历史提交中的旧字面量不会通过破坏性 Git 历史重写处理；它们必须被视为已经暴露并在提供方允许时轮换。本轮技术验收以当前树、构建日志和交付文件不再含字面量为准。

## Windows 构建警告设计

- 在顶层 CMake 对 CMP0175 显式选择与当前插件兼容的旧行为，避免新版 CMake 对第三方 `PRE_BUILD + DEPENDS` 写法发出开发警告。
- 在 `flutter_inappwebview_windows_plugin` 目标上仅禁用 WebView2 头文件已知的 C4458 警告，不降低其他目标的警告级别。
- 保留现有 WebView 生命周期补丁和安全导航行为。
- 新增配置契约测试，防止后续 Flutter 生成过程移除上述设置。

## 数据与兼容性

- 不删除或重命名任何本地、网盘视频、字幕或其他用户原始文件。
- 应用数据继续使用看影音专属支持和缓存目录。
- TMDB 无 Key、断网或服务不可用时继续跳过自动刮削，本地扫描与播放不受影响。
- `2.1.94.0` 使用原包标识覆盖 `2.1.93.0`，安装后复核已安装版本和桌面快捷方式。

## 测试与交付

每项生产行为遵循红—绿—重构：

1. 着色器准备失败与可空路径测试。
2. 播放器释放步骤失败隔离测试。
3. 迅雷配置缺失、完整配置和源码零字面量测试。
4. 版本、测试版标记、Windows-only 本轮交付文案一致性测试。
5. CMake 警告策略契约测试。
6. 相关定向测试、`flutter test --no-pub`、`flutter analyze --no-pub` 和格式检查。
7. `flutter build windows --release --no-pub`。
8. 生成签名 MSIX，验证 Identity、Version、Publisher、x64、签名和 SHA-256，复制桌面为 `看影音-2.1.94.msix`。
9. 使用 `Add-AppxPackage` 完成覆盖安装，复核 `Get-AppxPackage -Name com.kanyingyin.player` 为 `2.1.94.0`。
10. 检查 Git 状态和关键差异，只提交本轮相关文件；现有设置组件修改保持未暂存。
