# 关于页当前版本更新说明入口设计

## 目标和位置

在“设置 > 关于”页面现有“当前版本”条目正下方增加“更新说明”导航入口。入口位于同一个设置分组中，不调整“清除缓存”和“当前版本”的现有顺序、样式或数据来源。

入口标题为“更新说明”，辅助说明为“查看当前版本的更新内容”。Windows 与 Android 均显示该入口。

## 展示范围

用户点击入口后，只显示当前安装版本的更新说明，不展示全部历史版本：

- 使用 `AppVersion.current` 获取当前版本。
- 使用 `versionHistoryForCurrent()` 读取现有版本历史，不维护第二份更新文案。
- Windows 使用当前版本的双平台发布说明。
- Android 传入当前平台类型，显示 Android 专属的当前版本说明。

手动打开更新说明不会读取或写入 `SettingBoxKey.lastSeenVersion`，也不会影响下次升级时的首次启动更新弹窗。

## 组件边界

现有 `VersionChangelogDialog` 和 `VersionChangelogContent` 定义在 `init_page.dart` 中。为了让启动流程和关于页复用同一界面，将它们移动到职责单一的共享展示文件：

```text
lib/features/version/presentation/version_changelog_dialog.dart
```

`init_page.dart` 继续负责版本已读状态和自动弹窗时机，只引用共享弹窗。`about_page.dart` 只负责取得当前平台的当前版本说明并打开共享弹窗，不依赖启动页面。

共享组件保留现有标题、版本标签、日期、变更列表、滚动行为和“知道了”按钮，不改变升级时自动弹窗的外观与交互。

## 空数据处理

如果当前版本没有对应的版本历史，关于页不打开空对话框，而是显示“当前版本暂无更新说明”提示。自动升级弹窗继续沿用现有行为：历史为空时不显示，也不误展示旧版本内容。

## 兼容性边界

- 不新增网络请求、远程公告或外部链接。
- 不新建完整版本历史页面。
- 不改变应用启动、版本已读状态、快捷方式检查和缓存管理。
- 不修改当前版本号的展示方式。
- 除新增入口外，不修改设置页共享控件的内部层级、动画时长和动画曲线。

## 测试策略

测试按 RED-GREEN 顺序执行：

- 验证“更新说明”源码位置严格晚于“当前版本”，且仍处于相同设置分组。
- 验证入口使用 `AppVersion.current`、`detectAppPlatform().kind` 和 `versionHistoryForCurrent()`。
- 验证入口打开共享 `VersionChangelogDialog`，历史为空时显示明确提示。
- 调整现有更新日志组件测试的导入路径，确认组件抽取后渲染内容不变。
- 保留首次启动版本已读状态、当前版本文案和关于页内容测试。
