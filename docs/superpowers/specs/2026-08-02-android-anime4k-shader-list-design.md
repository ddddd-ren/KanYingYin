# Android Anime4K 着色器列表修复设计

## 现象

Android 播放器启用 Anime4K 后，mpv 报错无法打开一个由六个着色器绝对路径和分号组成的“文件名”。着色器已经安装在应用专属目录，但播放器无法加载，随后视频打开失败。

日志中的路径形态为：

```text
/data/user/0/com.kanyingyin.player/files/anime_shaders/a.glsl;/data/.../b.glsl
```

## 根因

`Anime4kShaderExecutor` 当前把全部路径用分号拼接，并通过 `change-list glsl-shaders set` 一次传给 mpv。

`glsl-shaders` 是 mpv 路径列表选项。Windows 使用分号作为路径列表分隔符，Unix 平台使用冒号。Android 按 Unix 规则解析，因此不会把分号识别为列表边界，而是把整串值当成单个路径。错误发生在着色器命令编码层，不是着色器复制、目录权限、GPU 渲染器或网盘中转层。

## 选定方案

启用 Anime4K 时不再自行编码平台相关的路径列表：

1. 使用 `change-list glsl-shaders clr ''` 清空播放器中可能残留的旧着色器。
2. 按效率档或质量档的既有顺序，对每个绝对路径分别执行 `change-list glsl-shaders append <path>`。
3. 全部追加成功后才把应用运行状态视为已启用。

mpv 的 `append` 操作只接收一个列表项，不解释路径列表分隔符，因此 Android 与 Windows 使用同一实现。六个着色器的组合、顺序和文件名保持不变。

## 失败处理

若清空或任意一次追加失败，执行器再次尝试清空 `glsl-shaders`，防止留下部分加载的着色器，然后保留原始错误和堆栈向上抛出。二次清空失败不能覆盖首次错误。

播放器控制器继续沿用现有安全降级：记录不包含媒体签名的诊断信息，把 Anime4K 标记为加载失败，并保持普通播放路径可用。关闭 Anime4K 仍只执行一次清空命令。

## 兼容性边界

- 不修改 Anime4K 效率档和质量档的官方着色器组合。
- 不修改 Android `auto`、`gpu`、`gpu-next` 的能力判断。
- 不修改 Windows 渲染器、硬件解码、字幕、网盘读取和播放器动画。
- 不修改或删除本地、网盘原始视频和字幕文件。
- 不使用按平台切换冒号或分号的实现，避免路径转义和盘符差异再次进入业务代码。

## 测试策略

测试按 RED-GREEN 顺序执行：

- 把现有“分号拼接 set 命令”测试改为“先清空、再按顺序逐条 append”，确认旧实现失败。
- 覆盖 Android 绝对路径，确保命令参数中不会出现由分号拼接的整串路径。
- 覆盖 Windows 盘符路径，确保逐条追加不会拆分 `C:\` 路径。
- 模拟第二个着色器追加失败，验证最后一次命令为清空，并重新抛出首次错误。
- 保留关闭 Anime4K、空目录、着色器准备失败和播放器状态降级测试。

定向测试通过后运行完整 `flutter test --no-pub`、`flutter analyze --no-pub`，并完成 Android 和 Windows Release 构建、签名与安装包验证。
