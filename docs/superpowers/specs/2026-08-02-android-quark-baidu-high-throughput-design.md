# Android 夸克与百度高码率读取优化设计

## 目标和范围

本次优化只提升 Android 平台从夸克网盘和百度网盘连续读取高码率视频时的吞吐。Windows、迅雷和其他提供方继续使用现有中转参数，网盘原始视频文件不被修改或删除。

验收重点是让 Android 夸克与百度中转充分使用读取器已经允许的六个主机连接，同时保持前台播放请求始终拥有一个调度槽位。缓存分段大小和总容量不变，避免以增加磁盘占用换取速度。

## 已确认的性能根因

夸克和百度远端读取器都把 `HttpClient.maxConnectionsPerHost` 设置为 6，但 Android 公共 Range 中转当前最多只允许 4 路远端读取，其中后台预取最多 3 路。播放器连续读取时，调度器无法使用读取器提供的另外两个连接。

中转以 4 MiB 为一段。每段完整下载并写入缓存文件后，本机 HTTP 服务才向播放器输出该段；启动阶段还会同时预取首段和尾段。因此，当前低并发和六段前向窗口会限制高码率资源的持续吞吐，尾段预热也可能短暂占用后台预取槽位。

本轮先修正可明确验证的调度器与读取器连接数不匹配。前台分段边下载边输出涉及半成品缓存可见性、取消、重试和长度校验，不与本次低风险参数调整混合实施。

## 方案选择

采用提供方定向的 Android 高吞吐参数：

- 总远端读取并发：6 路
- 后台预取并发：5 路
- 连续播放向前预取：10 段，约 40 MiB
- 分段大小：保持 4 MiB
- 最大缓存段数：保持 32 段，即 128 MiB

该方案让夸克和百度用满现有六连接上限，同时通过 `maxConcurrentPrefetch < maxConcurrentReads` 为前台读取保留一个槽位。相比统一提高所有 Android 网盘并发，它不会改变迅雷行为；相比边下载边输出，它不改变缓存文件的完整性契约和本机 HTTP 响应流程。

## 架构和数据流

公共中转启动接口新增强类型的 `providerType`，并继续保留 `providerKey` 作为每个用户来源的缓存命名键。`CloudPlaybackResolver` 从 `CloudSource.type` 直接传入提供方类型，旧夸克专用包装器显式传入 `CloudSourceType.quark`。这样不会把 `baidu-home` 等用户来源 ID 误当成固定提供方标识。

`CloudRangeRelayService` 保留平台能力信息，在 `start()` 校验完缓存命名键后根据 `providerType` 选择会话参数：

- Android 且提供方为 `quark` 或 `baidu`：使用高吞吐参数。
- Android 的迅雷及未知提供方：使用现有 Android 参数。
- Windows 的所有提供方：使用现有 Windows 参数。

提供方比较使用 `CloudSourceType` 枚举，不依赖用户可编辑的来源 ID 或面向用户的提供方名称。选出的参数继续通过现有 `CloudRangeRelaySession.start()` 传入，不改变读取器接口、缓存目录结构、Range 协议和播放租约生命周期。

播放进入连续读取后，前台请求获取当前分段；完成一个分段时调度最多十个后续分段。调度器最多并行执行五个预取，并始终允许前台请求优先取得第六个槽位。跳播仍通过现有预取代次失效机制取消旧方向任务。

## 错误处理和兼容性

远端鉴权、直链刷新、重连、Range 校验、失败状态发布和缓存清理全部沿用现有实现。参数选择不吞掉异常，也不增加自动重试。

夸克或百度服务端若实际限制连接数，现有 `HttpClient` 和读取器错误处理继续生效；本轮不绕过提供方限流，不拆分单个 Range，也不持久化新的配置。应用关闭、租约释放和孤立缓存清理行为保持不变。

## 测试策略

测试按先失败、后最小实现的顺序执行：

- 验证 Android 夸克选择 6 路总读取、5 路后台预取和十段前向窗口。
- 验证 Android 百度选择相同高吞吐参数。
- 验证 Android 迅雷和未知提供方仍为 4/3/6。
- 验证 Windows 的夸克、百度仍为 5/4/8。
- 验证播放解析器把来源 ID 继续作为缓存键，同时把 `CloudSource.type` 独立传给中转启动器。
- 使用延迟 Range 读取器验证高吞吐会话在连续播放时能达到五路后台并发，且不超过六路总并发。
- 保留缓存容量、Range 协议、跳播失效、关闭清理和错误处理测试。

定向测试通过后执行完整 `flutter test --no-pub`、`flutter analyze --no-pub` 和 Android Release 构建。由于本次是 Android 播放性能改动，同时按项目交付规则验证 Windows Release、生成并校验 MSIX，并将本版 APK、AAB 和 MSIX 复制到桌面。
