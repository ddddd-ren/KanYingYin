# Android 夸克自适应高速读取与系统栏联动设计

## 背景

Android `2.1.101` 的夸克原画播放已经通过本机 Range 中转实现并发预取。当前 Android 夸克和百度共用高吞吐参数：每段 `4 MiB`、最多 `6` 路远程读取、其中最多 `5` 路后台预取、向前预取 `10` 段，缓存上限为 `32` 段，即 `128 MiB`。夸克远程读取器的单主机连接上限同样为 `6`。

用户在 4K 夸克视频播放界面观察到约 `6.6 MB/s`，希望优先提高播放吞吐，并明确接受更高并发与约 `192 MiB` 临时缓存。现有诊断日志可以确认播放和网盘扫描流程，但没有记录调度器升降档、活跃并发和缓存压力，无法区分 CDN 单连接限制、预取不足或重连降速。

用户提供的 Android 平板对比图还显示：普通页面的底部系统手势区域出现独立黑边，状态栏背景没有与页面完全融合。当前播放器退出沉浸模式时会恢复 `setDecorFitsSystemWindows(true)`，Android `NormalTheme` 也没有统一声明系统栏颜色；因此普通页面、播放器和原生窗口分别控制系统栏，恢复顺序不同便可能产生黑边或颜色跳变。

## 已确认决策

- 仅优化 Android 夸克原画播放吞吐，目录浏览和媒体库扫描不在本轮性能范围内。
- 采用自适应高速调度，不固定长期使用最大并发。
- 保留 `4 MiB` 分段；默认使用 `6` 路连接和 `5` 路预取，播放发生前台缺块时提升到 `8` 路连接和 `7` 路预取。
- 临时分段缓存提高到 `48` 段，即最大约 `192 MiB`。
- 普通页面保留系统状态栏和手势条，但背景与当前页面或底部导航同色。
- 播放全屏继续彻底隐藏系统栏；边缘滑动临时唤出时使用播放器黑色背景和白色图标。
- 当前迭代仍为测试版；不自动推送、发布正式版或安装交付包。

## 目标

- Android 夸克原画播放在缓存跟不上前台请求时自动增加并发，减少高码率视频的缓冲等待。
- CDN、网络或播放地址不稳定时自动退回当前稳定档，不因激进并发放大重试。
- 前台播放请求始终优先于后台预取，并始终保留至少一路远程读取能力。
- 调度日志能说明何时升档、降档及其原因，但不得包含 Cookie、文件地址或其他凭据。
- Android 普通页面绘制到状态栏和底部手势区域，消除独立黑边，同时保持交互内容位于安全区内。
- 浅色、深色和 OLED 主题自动选择正确的系统图标明暗。
- 播放页、全屏、旋转、切后台和退出播放之间的系统栏颜色与可见性切换稳定。
- Windows、百度、迅雷、OpenList 和本地播放行为保持不变。

## 非目标

- 不绕过夸克官方鉴权、风控或下载地址校验。
- 不修改用户网盘文件，不把临时缓存变成永久离线下载。
- 不修改夸克目录分页、媒体库索引或 TMDB 扫描流程。
- 不增大单个分段到 `8 MiB`，避免拖慢首帧和跳播恢复。
- 不把夸克原始下载地址直接交给播放器，以免失去并发预取、地址刷新和请求头控制。
- 不隐藏普通页面的系统栏，不改变 Android 平板横屏策略。
- 不重排播放器控件、媒体库卡片或底部导航项目。

## 夸克自适应高速调度

### 参数与边界

为公共 Range 中转增加可选的自适应策略，静态基础参数与自适应上限分开表达：

| 参数 | Android 夸克基础档 | Android 夸克高速档 |
| --- | ---: | ---: |
| 分段大小 | `4 MiB` | `4 MiB` |
| 最大缓存段数 | `48` | `48` |
| 最大远程读取 | `6` | `8` |
| 最大后台预取 | `5` | `7` |
| 向前预取段数 | `10` | `14` |

高速档始终满足“后台预取上限小于总读取上限”，从而为播放器的前台缺块请求保留至少一路。夸克 `HttpClient.maxConnectionsPerHost` 设置为 `8`，调度器负责决定实际启用 `6` 路还是 `8` 路。百度继续使用现有固定 `6/5/10` 参数和 `128 MiB` 缓存，其他提供方继续使用各自现状。

### 升档信号

不使用固定网速阈值决定升档，因为文件码率、CDN 节点和测速采样窗口不同，单纯比较 `MB/s` 容易误判。调度器使用实际播放需求作为信号：

1. 播放器请求的分段命中完成缓存时不产生压力；复用正在下载的同段任务或新建远程读取时，记为一次前台缓存压力。
2. 第一次前台缓存压力立即把本会话提升到高速档，使新增的前向预取可以使用最多 `7` 路后台连接。
3. 正在下载的同段任务继续由缓存的 in-flight 去重处理，不重复建立远程请求；它只作为“播放器已经追上预取”的升档信号。
4. 高速档只作用于当前播放会话；关闭播放器后状态不持久化。

分段缓存需要向会话返回“命中完成缓存、复用进行中任务或新建远程读取”三种获取结果，使调度器可以准确识别前台缓存压力，而不是根据等待时间猜测。

### 降档与恢复

收到远程读取器的重新连接或播放地址刷新事件时，调度器立即退回基础档。已经开始的请求允许正常完成，不强行取消或截断；尚未开始的预取继续排队，并按新的并发上限启动。

退回基础档后，如果后续再次出现前台缓存压力，可以重新进入高速档。升降档不使用周期性计时器，也不根据单次吞吐采样频繁来回切换，避免震荡。远程读取器原有的超时、鉴权刷新和有限重试规则保持不变。

### 调度日志与状态

仅在以下状态变化时记录一条信息日志：

- 基础档提升为高速档，原因固定为 `foreground_cache_pressure`。
- 高速档退回基础档，原因区分 `reconnecting` 和 `refreshing`。
- 会话关闭时记录累计远程读取字节数和最终档位。

日志包含提供方名称、基础/高速档、并发上限、预取上限和脱敏原因，不记录远程 URI、请求头、Cookie、文件 ID 或本地缓存路径。现有播放器顶部读取速度继续显示实际五秒窗口吞吐，不新增常驻调试控件。

## Android 系统栏联动

### 职责划分

系统栏职责按“原生层控制几何与可见性，Flutter 控制页面颜色与图标样式”拆分：

- Android 原生层负责窗口是否边到边、系统栏显示/隐藏、滑动临时唤出和生命周期恢复。
- Flutter 根组件负责普通页面的透明系统栏、主题背景延伸及图标明暗。
- 播放页负责播放器场景的黑色底层和白色系统图标。

避免普通页面、AppBar 和播放器分别调用互相覆盖的全局系统栏模式。

### 普通页面

Activity 创建后即进入正常边到边模式：

- Android 11 及以上使用 `window.setDecorFitsSystemWindows(false)`。
- 状态栏和导航栏颜色均为透明。
- Android 10 及以上关闭系统栏对比度强制，避免系统额外生成黑色或浅色遮罩。
- 系统栏保持可见，不启用全屏隐藏。

Flutter 应用根部根据当前主题发布统一的 `SystemUiOverlayStyle`。浅色主题使用深色状态栏和导航栏图标，深色及 OLED 主题使用浅色图标。根部背景延伸到系统栏区域，页面中的列表、按钮和标题仍通过 `SafeArea` 避让系统状态栏。

紧凑布局的底部 `NavigationBar` 外层使用同色背景包裹底部 `SafeArea`，让手势条所在区域与导航栏成为同一连续色面。现有导航高度、图标、标签、选中状态和动画保持不变。

### 播放页面与全屏

进入播放页后，页面发布播放器专用系统栏样式：透明系统栏、白色图标、黑色底层。这样在非全屏状态或系统栏临时可见时，顶部和底部均与播放器背景一致。

进入全屏后继续使用现有持久沉浸控制器隐藏状态栏和导航栏，并保持 `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`。边缘滑动临时唤出的系统栏覆盖在黑色播放器底层上，不出现白色或主题色闪烁。

退出全屏时不再恢复 `setDecorFitsSystemWindows(true)`，而是恢复“正常边到边且系统栏可见”。离开播放路由后，Flutter 根组件重新发布当前应用主题的系统栏样式。

### 生命周期与兼容

原生控制器继续在 Activity 恢复前台、窗口重新获得焦点和配置变化时重新应用当前模式：

- 沉浸请求为真时重新隐藏系统栏。
- 沉浸请求为假时保持正常边到边并显示系统栏。

Android 10 及以下使用兼容的 `systemUiVisibility` 标志实现相同结果。重复应用必须幂等，不创建轮询或持续计时器。画中画、软键盘、目录选择器和权限弹窗返回后也必须恢复正确模式。

## 数据流

### 夸克播放

1. `QuarkDriveClient` 继续解析原画下载地址和受信请求头。
2. `CloudRangeRelayService` 仅在 Android 夸克来源选择自适应策略。
3. 会话以基础档启动并预取文件头、文件尾和顺序前向分段。
4. 播放器请求未缓存分段时，缓存报告前台缺块，会话把调度器提升到高速档。
5. 调度器最多执行 `8` 路读取，其中最多 `7` 路为后台预取。
6. 远程连接或地址刷新时退回基础档，缓存的已完成分段继续可用。
7. 会话关闭时清理本次临时目录，沿用现有孤立缓存清理规则。

### 系统栏

1. Activity 启动时进入正常边到边模式。
2. 应用主题决定普通页面背景及系统图标明暗。
3. 进入播放路由后切换为播放器黑色样式。
4. 进入全屏后原生层隐藏系统栏；临时唤出时仍沿用播放器样式。
5. 退出全屏恢复可见的边到边系统栏；退出播放路由恢复应用主题样式。

## 错误处理

- 自适应策略异常不得绕过现有 URI 信任校验、Content-Range 校验、鉴权刷新或请求重试上限。
- 提升并发后出现重新连接或地址刷新时只降档，不删除已完成缓存，不重建播放器。
- 缓存目录创建或写入失败时沿用现有中转失败提示，不回退到不受控的直链播放。
- 系统栏原生调用重复或生命周期交错时以当前 `immersiveRequested` 为唯一可见性状态，不恢复过期的窗口几何状态。
- Flutter 路由退出或组件销毁后不得继续覆盖新页面的系统栏样式。

## 测试设计

### 自动化测试

- 调度器测试验证 Android 夸克基础档为 `6/5/10`、高速档为 `8/7/14`、缓存为 `48 × 4 MiB`。
- 缓存测试验证完成命中、in-flight 复用和新建读取三种结果，不为同一分段创建重复请求。
- 会话测试验证首次前台缺块触发 `6→8`，重新连接或刷新触发 `8→6`，再次缺块可以重新升档。
- 并发测试验证任何时刻远程读取不超过当前档位，并始终限制后台预取低于总并发。
- 提供方选择测试验证自适应策略只用于 Android 夸克，Windows 夸克及 Android 百度保持现有参数。
- 日志测试验证调度原因可见且不包含 Cookie、URI、文件 ID 或请求头。
- Flutter 组件测试验证普通页面系统栏随浅色、深色和 OLED 主题切换，底部安全区使用导航栏背景色填充。
- 播放页测试验证黑色系统栏样式、全屏进入退出及离开路由后的主题恢复。
- Kotlin 单元与契约测试验证正常边到边、沉浸隐藏、退出沉浸、焦点恢复和配置变化状态机。
- 完整执行 `flutter test`、`flutter analyze --no-pub` 和 Android 原生单元测试。

### 构建与包级验证

- Android APK/AAB 和 Windows Release 构建成功。
- APK v2 签名、AAB 严格签名和 MSIX 签名有效。

### Android 实机验收

使用与 `2.1.102` 相同的设备、夸克原画文件和网络环境：

- 连续播放至少 `60` 秒，记录平均读取速度、首帧时间、拖动恢复时间和卡顿次数。
- 高码率播放发生前台缺块时日志出现 `6→8`，稳定读取期间不超过 `8` 路。
- 目标是读取速度明显高于当前约 `6.6 MB/s`，并且不增加重连或卡顿；实际峰值仍受夸克 CDN 和网络上限约束，不能仅凭自动化测试宣称固定网速。
- 片头播放、连续播放、跨章节拖动、切后台恢复和播放地址刷新均可继续播放。
- 普通媒体库页面的状态栏与页面同色，底部手势区域与底部导航同色且没有黑边。
- 浅色、深色和 OLED 主题下系统图标清晰可见。
- 播放页系统栏为黑色背景与白色图标；全屏时系统栏隐藏，边缘滑动可临时唤出。
- 旋转设备、弹出系统授权页、切后台再返回及退出播放器后，系统栏状态正确恢复。

## 风险与回滚

- 夸克 CDN 可能按账号、节点或并发数限速；自适应升档若触发不稳定，会通过现有重新连接事件退回基础档。
- `192 MiB` 是单播放会话的最大磁盘缓存，不代表启动即占满；关闭会话后按现有流程删除。
- 边到边布局可能暴露个别弹窗或页面遗漏安全区的问题，因此必须覆盖目录选择、设置页、媒体详情和播放器的实机回归。
- 系统栏几何与样式分层后，路由切换时可能出现一帧颜色跳变；根级主题样式和播放页局部覆盖必须用组件测试及截图检查锁定。
- 性能改动与系统栏改动分开提交。若夸克高速档出现回归，可只回滚自适应策略并保留系统栏修复；若边到边布局出现兼容问题，可只回滚正常模式系统栏联动并保留现有全屏沉浸控制器。
