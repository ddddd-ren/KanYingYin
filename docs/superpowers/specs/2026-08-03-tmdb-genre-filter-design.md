# TMDB 类型标签筛选与刮削名称清理设计

## 目标

为媒体库中已有的本地和个人网盘资源增加 TMDB 类型标签筛选。媒体库继续优先展示本地缓存；已经刮削且具有 TMDB ID、但尚未保存类型数据的作品，在后台增量补齐类型。没有 API Key、断网或 TMDB 请求失败时，扫描、浏览和播放仍可正常使用。

同时扩展 TMDB 搜索词清理规则，识别用户截图中的发布信息，避免这些规格词进入 TMDB 搜索词，并保护正常片名不被误删。

## 范围

本测试版包含：

- 从 TMDB 详情响应读取中文类型名称并保存到本地与网盘索引。
- 为已有已刮削资源后台补齐缺失类型。
- 媒体库按一个或多个 TMDB 类型筛选。
- 类型筛选与来源、关键词筛选组合使用。
- 提供后台状态和手动重试入口。
- 清理截图中出现的新增发布词组合。

本测试版不包含：

- 用户自定义标签、收藏夹或标签编辑。
- 离线维护一套 TMDB 类型编号到中文名称的映射。
- 对尚未完成 TMDB 匹配的资源自动执行完整刮削。
- 因补齐类型而覆盖用户锁定的标题、简介、海报等字段。

## 数据模型

`TmdbMetadata` 增加不可变的 `List<String> genres`。JSON 反序列化在旧缓存缺少字段、字段类型错误或包含空值时返回空列表；序列化仅保存清理后的非空类型名称。`copyWith`、相等性和元数据合并策略同步保留该字段。

本地媒体沿用 `LocalMediaIndexItem.tmdb` 中的 `TmdbMetadata`。网盘索引增加 `tmdbGenres`，并同步覆盖构造、复制、TMDB 替换和仓储 JSON 读写。旧网盘索引没有该字段时按空列表读取。

`TmdbClient` 从详情接口的 `genres[].name` 解析类型，按接口顺序去空、去重。中英文详情回退合并时优先使用中文响应的非空类型；中文没有类型时采用英文响应结果。

媒体库聚合模型为每个 `MediaLibrarySeries` 暴露不可变的 `genres`。系列下多集或多版本的类型按稳定顺序合并去重，避免同一类型重复出现。

## 后台增量补齐

媒体库先读取现有本地和网盘缓存并立即可用。控制器随后收集符合以下条件的作品：

- 已保存有效 TMDB ID 和媒体类型。
- 当前类型列表为空。
- 同一 TMDB 媒体类型与 ID 组合尚未在本轮请求。

补齐任务复用现有 TMDB 凭据、客户端和仓储，不创建独立缓存。请求按去重后的作品执行，成功后仅补充类型字段并持久化到所有对应本地或网盘条目，不修改标题、简介、评分、海报、背景图、手动名称或字段锁定状态。每次成功持久化后，媒体库可重新聚合并更新可用筛选项。

没有 API Key 时不启动请求。网络或 TMDB 错误按单个作品隔离，不中断其余任务，也不阻塞媒体库和播放。界面只显示汇总状态，避免连续错误弹窗。用户可通过“刷新类型标签”重试仍为空的已匹配作品。

## 筛选规则

类型选项从当前媒体库中已有的非空类型动态生成，去重后按中文名称排序。没有任何类型数据时不显示空的类型菜单。

用户可以选择多个类型。系列命中任意一个已选类型即可保留；未选择类型时不限制结果。组合顺序为：

1. 先按媒体来源筛选。
2. 再按关键词搜索系列名称。
3. 最后按已选 TMDB 类型执行“任一匹配”。

因此来源、关键词和类型之间必须同时满足，而多个已选类型之间采用“或”关系。切换来源时，仍然有效的已选类型保留；当前来源不再提供的已选类型从选择中移除，避免出现无法解释的空结果。

筛选计算放在独立的纯 Dart 查询组件中，界面只负责保存选择并展示结果，便于覆盖组合规则和边界条件。

## 界面

媒体库搜索框下方、现有来源筛选附近增加紧凑的“类型”筛选按钮。按钮打开复选菜单，列出当前可用类型并提供“清除”。未选择时显示“类型”，选择后显示“类型 N”，不在主界面横向铺满所有标签。

后台补齐期间在类型入口附近显示轻量进度状态；媒体库仍可搜索、切换来源、展开系列和播放。补齐失败后保留“刷新类型标签”入口，不弹出逐条错误。筛选结果为空时沿用现有空结果区域，并明确这是筛选结果而非媒体库没有内容。

控件使用现有 Material 图标、菜单、间距、圆角和文字层级，不改变媒体卡片、展开动画、排序、播放入口或 TMDB 刮削交互。

## TMDB 搜索词清理

现有清理器已覆盖 `REMUX`、`UHD`、`PROPER`、`TrueHD 7.1` 和 `DreamHD`。本轮补充：

- `DoVi`。
- 独立出现的 `HD MA`。
- `Multi Audio` 和数字音轨写法，例如 `14Audio`。
- 发布规格尾部的版本标记 `V3`、`V4`。
- 发布片段中的地区标记 `US`。

新增规则采用发布片段上下文识别，不全局删除可能属于片名的短词。`US` 只在与 `PROPER`、`REMUX`、`UHD`、音轨等发布规格相邻的后缀片段中清理；单独的电影名 `Us` 必须保留。`V3`、`V4` 也只在发布规格片段中清理，正常片名中的字母和数字组合保持不变。

截图中的以下后缀组合必须能从“片名 + 后缀”清理为“片名”：

- `REMUX -HD MA TrueHD 7 1`
- `PROPER US REMUX -HD MA TrueHD 7 1`
- `PROPER US REMUX -HD MA TrueHD 7 1`
- `UHD REMUX TrueHD7 1-DreamHD`
- `V4 UHD REMUX TrueHD7 1 Multi Audio-D`
- `V3 UHD REMUX DoVi TrueHD7 1 14Audio`

## 测试策略

实现遵循测试先行：

- `TmdbMetadata` 新旧 JSON 往返、空值清理、复制与合并。
- TMDB 详情解析中文类型、稳定去重和中英文回退。
- 本地与网盘索引的类型持久化及旧缓存兼容。
- 媒体库聚合的系列类型合并。
- 单选、多选任一匹配、来源与关键词组合、无类型数据和无结果。
- 后台补齐去重、成功持久化、部分失败、无 API Key 和手动重试。
- 类型筛选菜单、选择数量、清除和后台状态的组件测试。
- 截图中的全部名称清理样例，以及 `Us`、`V字仇杀队` 等防误删样例。

最终执行完整 `flutter test`、`flutter analyze`、Windows Release 构建和项目规定的 MSIX 交付核验。
