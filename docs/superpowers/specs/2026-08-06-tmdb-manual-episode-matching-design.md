# TMDB 剧集手动匹配设计

## 目标

为本地视频和个人网盘资源增加统一的“匹配剧集”功能。用户可以先选择 TMDB 电视剧作品和季度，再把每个实际视频手动映射到该季度的具体集。保存后，本地详情、网盘选集、观看历史和播放器选集统一显示 TMDB 集名。

功能只修改看影音内部的元数据与映射，不修改、移动或重命名本地文件和网盘文件，也不改变播放路径、远程 ID、字幕关联或播放身份。

## 范围

本期同时支持：

- 本地媒体库中的电视剧系列。
- 网盘资源页中的电视剧作品和季度资源。
- 可靠自动预匹配、逐文件手动选择、清除单个文件的手动映射。
- 本地详情、网盘选集、观看历史和播放器选集的标题一致性。
- 网盘重新扫描后恢复手动映射。

本期不包含：

- 修改原始文件名、目录名或网盘远程路径。
- 按文件排序强行推断集号。
- 跨作品批量编辑。
- 自动删除失效的旧规则；失效规则只是不再命中当前资源。

## 方案选择

采用共享“剧集手动匹配”模块，并分别接入本地和网盘保存适配器。

未采用两套独立实现，因为两端的预匹配、季度选择、错误处理和标题格式会逐渐分叉。未采用直接修改网盘索引缓存，因为网盘重新扫描会重建索引并覆盖缓存中的手动结果。

共享模块负责交互状态、TMDB 季度加载、严格自动预匹配、赋值校验和结果输出。本地与网盘适配器只负责读取资源、保存映射以及刷新各自的媒体库。

## 交互流程

本地系列和网盘剧集菜单都增加“匹配剧集”入口。

1. 复用现有 TMDB 搜索对话框选择作品，但逐集匹配只接受电视剧候选。
2. 选中作品后进入共享的“匹配剧集”页面。
3. 页面顶部显示海报、作品名和季度选择控件。
4. 选择季度后加载该季度的 TMDB 集列表。
5. 页面逐行显示原始视频名称和当前映射结果。
6. 可靠解析出的文件自动预选对应集；无法解析或存在冲突的文件显示“未匹配”。
7. 点击文件行可选择该季度的具体集，也可选择“保留原名”或“恢复自动识别”。
8. 允许多个视频映射到同一集，以支持同一集的不同画质、发布组或剪辑版本。
9. 点击“完成”后批量保存；取消时不写入任何映射。

保存后，已匹配项显示“第 N 集 + TMDB 集名”，未匹配项继续显示原文件名。

## 可靠预匹配规则

自动预匹配只接受结构化季集证据，不根据文件在列表中的位置猜测。

可靠证据包括：

- 文件名明确包含 `S01E01`、`第1季第1集`、`EP01` 等季集格式。
- 文件名包含明确集号，父目录能提供有效剧名。
- 季号来自 `Season 2`、`S02`、`第2季` 等明确季度目录，集号来自文件名。

以下情况保持未匹配：

- 只有 `01.mkv`，且父目录是“电视剧”“剧集”“TV”等泛目录，无法确认作品身份。
- 文件名中的数字实际是年份、`4K`、`8K`、码率或电影标题数字。
- 文件名季号与目录季号冲突。
- 无法确认正整数集号或有效作品名。

“保留原名”是显式手动状态，会持续压制自动解析；“恢复自动识别”才会清除手动状态并重新使用解析结果。

优先级固定为：手动逐集映射或手动保留原名 > 可靠自动解析 > 未匹配并保留原名。

## 共享领域模型

共享模块使用两个核心模型：

- `ManualEpisodeMatchItem`：稳定资源标识、原始名称、现有季号、现有集号、自动解析证据和当前匹配状态。
- `ManualEpisodeAssignment`：资源标识、TMDB 作品身份、季度、集号以及 `mapped`、`keepOriginal`、`restoreAutomatic` 三种操作状态。

这些模型不提供文件移动、重命名或删除能力。界面只接收共享模型，不直接依赖本地路径 API 或具体网盘客户端。

保存前统一校验：

- 每个输入资源的稳定标识必须唯一。
- 已选择的集必须属于当前 TMDB 季度。
- 允许部分资源保持未匹配。
- 允许多个资源选择同一集。

## TMDB 数据加载

现有搜索流程继续负责候选检索和电视剧作品选择。进入逐集页面后：

- 先读取选中作品的完整详情和季度摘要。
- 用户选择季度后，按需请求该季度详情和逐集名称。
- 已缓存的作品或季度资料继续复用现有 TMDB 缓存。
- 逐集匹配不依赖自动识别出的季度集合，因此即使所有文件都未识别季号，用户仍可手动选择任意有效季度。
- 只把用户实际选择的季度详情并入保存的 TMDB 元数据，避免无界请求所有季度。

## 本地持久化

本地适配器使用现有本地媒体索引和批量更新能力：

- 把选中的 TMDB 作品资料和已加载季度的逐集名称保存到 `LocalMediaIndexItem.tmdb`。
- 每个文件只更新手动选择的 `seasonNumber`、`episodeNumber` 和手动覆盖状态。
- 手动选择的作品标记为 `TmdbMatchOrigin.manual`。
- 不把 TMDB 集名写入原始文件标题或解析标题字段。展示标题始终从当前 TMDB 元数据动态解析，使语言或资料更新后不会残留旧集名。
- 增加能显式清空季号、集号的专用映射更新方法，避免现有 `copyWith` 的空值保留语义阻止“保留原名”。
- “保留原名”把 `manualOverride` 保持为 `true` 并清空季号、集号；“恢复自动识别”清除手动覆盖并重新运行严格解析器。
- 所有本地资源先完成校验，再通过批量接口一次提交。

## 网盘持久化

网盘索引是扫描结果缓存，不能作为手动映射的唯一真相来源。新增独立的 `CloudEpisodeMatchRule` 仓储：

- 规则键由 `sourceId + remoteId + normalizedRemotePath` 组成。
- 规则记录 `mapped` 或 `keepOriginal` 模式、TMDB 媒体类型、TMDB 作品 ID、季度、集号和更新时间。
- “保留原名”保存 `keepOriginal` 规则并压制扫描结果；“恢复自动识别”才删除该视频对应的手动规则。
- 保存成功后立即通过网盘索引仓储更新当前索引，使页面无需重新扫描即可刷新。
- 后续扫描先按现有规则识别视频，再应用手动映射规则覆盖季号、集号和剧集类型。
- 当远程 ID 或路径发生变化时，旧规则不再命中，避免把旧映射套用到另一个视频。
- 网盘作品的 TMDB 记录保存已选择作品及季度资料，供标题解析、海报和季度展示复用。

网盘手动映射优先于自动识别，但不会改写远程文件名、路径、ID 或字幕引用。

## 标题贯通

最终展示标题统一由现有 `TmdbEpisodeTitleResolver` 生成，不在各页面重复拼接。

- 本地详情继续读取 `LocalMediaIndexItem.displayTitle`。
- `LocalPlaybackEntry.fromIndexItem()` 传递 `item.displayTitle`。
- 本地页面构建播放请求时使用 `item.displayTitle`，不再退回去扩展名的原文件名。
- 统一媒体库中的本地和网盘剧集继续通过 TMDB 元数据、季号和集号生成名称。
- 网盘资源集合把最终名称写入 `CloudFileEntry.name`，`CloudPlaybackTarget.title` 原样带入播放会话。
- 播放器选集继续读取 `Road.identifier`，但该列表必须来自上述最终展示标题。
- 观看历史重新打开本地或网盘剧集时复用统一媒体库中的最终名称。

未匹配项始终回退原始资源名称。

## 失败处理

- 无 TMDB API Key 时提示配置，不创建或修改任何手动映射。
- 作品详情或季度详情加载失败时保留当前页面并显示错误，不写入映射。
- TMDB 返回空季度或空集列表时禁止保存到不存在的集。
- 保存期间禁用重复提交。
- 批量保存失败时不关闭页面、不显示成功提示，并恢复保存前的映射快照。
- 网盘即时索引刷新失败但规则已经保存时，明确提示将在下次加载或扫描时生效；原始网盘浏览和播放继续可用。
- 任何 TMDB、仓储或网络错误都不能阻断未刮削资源的本地扫描、网盘浏览和播放。

## 测试策略

新增或扩展以下覆盖：

- 严格自动预匹配：明确季集格式、季度目录、泛目录、年份和画质数字、季号冲突。
- 匹配状态：未匹配回退、手动修改、明确保留原名、恢复自动识别、多个视频对应同一集。
- TMDB 加载：只接受电视剧、按需加载所选季度、空季度和请求失败。
- 本地持久化：批量保存、显式清空、JSON 往返、失败回滚和手动来源保护。
- 网盘持久化：规则 JSON 往返、即时索引更新、重新扫描后恢复、远程身份变化后不误套用。
- 界面流程：选择作品、选择季度、自动预选、逐项修改、部分未匹配、取消和完成。
- 播放链路：本地、网盘和观看历史进入播放器后，`Road.identifier` 使用 TMDB 集名。
- 回退边界：无 Key、断网、季度请求失败和保存失败时播放仍可用。

## 验收与交付

实现完成后依次执行：

1. 相关定向测试。
2. 完整 `flutter test --no-pub`。
3. `flutter analyze --no-pub`，不得有错误。
4. Windows Release 构建。
5. 按项目发布门禁记录当前已安装版本，升级下一测试版版本号，更新 `RELEASE_NOTES.md` 和 `lib/utils/version_history.dart`。
6. 生成并验证签名 MSIX，核对清单版本，并复制为桌面的 `看影音-版本号.msix`。
7. 自动提交前检查 `git status --short` 和关键 diff，只提交本轮相关文件，继续排除用户已有的 `test/library_genre_backfill_service_test.dart` 改动。

最终验收以界面、持久化、重新扫描和播放器选集中的实际集名同时正确为准，不能只以索引数据或构建成功作为完成依据。
