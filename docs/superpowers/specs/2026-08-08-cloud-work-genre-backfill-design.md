# 云端作品 TMDB 题材补齐设计

## 背景

部分夸克网盘电影已正确匹配 TMDB，但历史作品记录的 `metadata.genres` 为空。分类聚合优先读取作品记录，因此这些动画电影只能进入“电影”，不能同时进入“动漫”。现有题材补齐服务只处理本地索引和云文件索引，没有处理 `CloudWorkTmdbRecord`。

## 目标

- 对状态为 `matched`、TMDB ID 有效且题材为空的云端作品记录补抓 TMDB 详情。
- 只更新题材，不重新执行搜索或改变既有 TMDB 匹配结果。
- 补齐后，动画电影同时进入“动漫”和“电影”。
- TMDB 不可用、API Key 缺失或请求失败时，不影响本地扫描、网盘浏览和播放。

## 设计

扩展 `LibraryGenreBackfillService`，注入 `CloudWorkTmdbRepository`。服务在现有本地索引和云文件索引目标之外，收集满足以下条件的作品记录：

- `status == matched`
- `metadata != null`
- `metadata.id > 0`
- `metadata.genres.isEmpty`

补齐目标按 `(mediaType, tmdbId)` 去重。每个目标调用一次 `ITmdbClient.details`，成功取得非空题材后：

1. 使用 `metadata.copyWith(genres: details.genres)` 更新对应作品记录；
2. 更新同一 TMDB ID 对应的本地索引和云文件索引；
3. 保留标题、简介、评分、海报、匹配来源、规则版本等其他字段不变。

单个目标失败时只增加失败计数并继续处理其他目标。API Key 为空时不发起请求，也不修改数据。

## 数据流

`MediaCategoryRuntime` 初始化题材补齐服务后，服务读取当前本地索引、云文件索引和云作品记录，按 TMDB 身份合并补齐目标。写回完成后，分类聚合器从作品记录获得“动画”题材，现有双入口分类规则将动画电影同时归入“动漫”和“电影”。

## 测试

- 回归测试：已匹配且题材为空的云作品记录会调用详情接口并写回题材。
- 保留性测试：补齐题材时既有 TMDB ID、标题和匹配状态不变。
- 去重测试：相同 TMDB 身份在作品记录和文件索引中只请求一次详情。
- 分类测试：补齐后的动画电影同时属于“动漫”和“电影”。
- 失败测试：详情请求失败不阻断其他作品补齐。

## 非目标

- 不重新搜索或重新选择 TMDB 匹配结果。
- 不根据文件名猜测“动画”题材。
- 不修改用户原始视频文件。
