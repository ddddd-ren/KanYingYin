# 看影音 Windows 1.0.7 与 Android 1.0.4 正式版设计

## 目标

将当前 `2.1.157` 测试版中已经完成的 Windows 与手机版 Android 更新整理为正式版：

- Windows 正式版版本号为 `1.0.7`，交付 Inno Setup EXE 安装程序。
- Android 手机版正式版版本号为 `1.0.4`，交付 `mobile` flavor 的签名 APK 和 AAB。
- Android TV 正式版、测试版及 GitHub 发布无限期暂停；不构建、不上传、不宣传 `tvTest` flavor 或个人 TV 预置包。
- 正式版说明面向普通用户，分别描述各平台实际可用的能力。

## 版本策略

Windows 与 Android 延续现有的独立正式版版本线：

- `pubspec.yaml` 与 Windows 应用版本使用 `1.0.7+10007`。
- `lib/core/app_version.dart` 使用 `1.0.7`。
- Android `mobile` flavor 使用 `versionName 1.0.4`、`versionCode 10004`。
- 保留 `msix_config` 时只同步为 `1.0.7.0`，不生成 MSIX。

Android 正式版版本必须由构建脚本和 Gradle 配置共同校验，避免错误继承 Windows 的 `1.0.7`。版本一致性测试需要覆盖 Windows、Android mobile、发布说明和弹窗文案。

## 更新内容筛选

### Windows 1.0.7

Windows 弹窗和发布说明综合 `2.1.137` 至 `2.1.157` 中适用于 Windows 的内容：

- 本地剧集支持单集重新识别、手动匹配 TMDB、修正季度与集数，并隔离冲突剧集。
- 安装向导始终显示目录选择页，安装目录完全由用户选择，不要求存在 D 盘。
- 本地与网盘统一 TMDB 查询、候选排序和身份，清理位深等发布标签，改善作品匹配。
- 新增自动、HDR 直通和 HDR 转 SDR 色彩方案，并补充脱敏播放诊断信息。
- 改善剧场版、动漫电影、电视剧和电影分类，动画电影可同时出现在动漫与电影入口。
- 云盘外挂字幕显示原始文件名，修复重复 UTF-8 BOM 导致部分 ASS 字幕无法加载。
- 修复作品子目录中的裸集号识别，以及搜索无结果时误报“视频已隐藏”。

### Android 1.0.4

Android 弹窗和发布说明只包含手机版 `mobile` flavor 实际适用的共享更新：

- 改善剧场版 TMDB 匹配和电影、动漫、电视剧分类。
- 动画电影可同时显示在动漫与电影入口，动画电视剧可同时显示在动漫与电视剧入口。
- 云盘外挂字幕显示原始文件名。
- 修复重复 UTF-8 BOM 导致部分 ASS 字幕无法加载。
- 修复作品子目录中的裸集号分集识别。
- 修复搜索无结果时误报“视频已隐藏”。
- 继续说明无 TMDB Key、断网或请求失败时，扫描、浏览和播放仍可使用。

Android 文案不得出现以下 TV 专属内容：

- 遥控器焦点和方向键交互。
- 手机扫码配置电视。
- 电视横屏、海报墙、电视缓存和 Android 9 TV 调优。
- Leanback、海信电视验收、`tvTest` flavor 或个人 TV 预置包。

## 文件改动范围

正式版实现仅修改版本与发布契约相关文件，以及为双平台正式版版本校验所需的测试和构建配置：

- `pubspec.yaml`
- `lib/core/app_version.dart`
- `android/app/build.gradle.kts`
- `tool/android/build_signed_release.ps1`
- `UPDATE_DIALOG_COPY.md`
- `RELEASE_NOTES.md`
- `lib/utils/version_history.dart`
- `README.md`
- 版本一致性、发布文案和打包契约测试

不为本次发布重构业务功能，不删除历史版本记录，不修改 TV 功能实现。

Android TV 发布暂停是持续生效的项目决定，不只针对本次正式版。除非用户以后明确恢复，否则后续 Windows 和手机版 Android 发布同样不得生成 TV 产物、TV 标签或 TV Release。

## 构建与验证

### 发布前状态

- 记录当前 Windows EXE 卸载项、安装目录和 `kanyingyin.exe` 产品版本。
- 检查当前用户下是否存在旧 MSIX。
- 检查 `git status --short`，保留所有非本轮改动。

### 质量门槛

- 先更新正式版契约测试，并确认旧版本配置不能通过目标测试。
- 运行正式版聚焦测试。
- 运行完整 `flutter test --no-pub`。
- 运行 `flutter analyze --no-pub`，要求无错误。
- 运行 Windows Release 构建。

### Windows 产物

- 使用现有 Inno Setup 工作流生成 EXE，不生成 MSIX。
- 校验 Release 主程序产品版本和安装器版本均为 `1.0.7`。
- 将安装器复制到桌面，文件名遵循项目约定。
- 记录文件大小、SHA-256 和 Authenticode 状态。
- 不自动安装新正式版。

### Android 产物

- 只调用 `tool/android/build_signed_release.ps1 -Flavor mobile`。
- 生成包名为 `com.kanyingyin.player` 的 `1.0.4 (10004)` APK 和 AAB。
- 校验 APK v2 签名、AAB 严格签名和 Full 原生媒体包。
- 不调用 `build_tv_test.ps1` 或 `build_personal_tv.ps1`。
- 不生成包名为 `com.kanyingyin.player.tvtest` 的产物。
- 不创建或推送 Android TV 标签、GitHub Release 或任何 TV 下载资产。

## Git 与 GitHub 发布

- 检查关键 diff，只提交本次版本、文案、测试和构建契约改动。
- 使用简洁中文提交信息并推送 `main`。
- 创建并推送标签 `v1.0.7`。
- 创建标题为“看影音 1.0.7 正式版”的 GitHub Release。
- Release 只上传三个资产：Windows `1.0.7` EXE、Android `1.0.4` APK、Android `1.0.4` AAB。
- 上传后逐项比较远端大小和 SHA-256，再发布为 latest、非草稿、非预发布。
- 最终复查远端 `main`、标签、Release 状态和本地工作区。

## 验收边界

本次完成标准是版本、文案、自动化测试、静态分析、Windows Release、Inno Setup EXE、Android mobile APK/AAB、签名、哈希、Git 和 GitHub Release 全部核对完成。

未进行的实机安装或播放验收必须明确报告，不能用构建成功代替。Android TV 不属于本次交付范围，也不能出现在发布资产或用户弹窗中。
