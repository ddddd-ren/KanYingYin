# Windows 1.0.8 正式版发布设计

## 当前状态与版本代差

- GitHub 最新正式版为 Windows 1.0.7，标签为 `v1.0.7`。
- Windows 1.0.7 已综合到测试版 2.1.157。
- 本地源码和已安装 EXE 均为测试版 2.1.158。
- 正式版与本地测试版相差 1 代，尚未进入正式版的测试版本只有 2.1.158。
- 旧 MSIX 未安装。

因此，本次 Windows 正式版从 1.0.7 递增为 1.0.8，构建号为 10008。

## 发布范围

本次只发布 Windows 1.0.8 正式版：

- Windows 应用版本：`1.0.8+10008`
- Windows EXE 安装器版本：`1.0.8`
- GitHub 标签：`v1.0.8`
- GitHub Release 标题：`看影音 1.0.8 正式版`
- GitHub Release 资产：`KanYingYin-1.0.8.exe`

本次不发布其他平台：

- Android 手机继续保持 `1.0.4 (10004)`，不修改 Android 正式版本号，不构建 APK 或 AAB。
- Android TV 发布继续无限期暂停，不运行 `tvTest`，不生成或上传任何 TV 产物。
- 历史 MSIX 配置只同步 Windows 兼容版本，不生成 MSIX。

## Windows 用户弹窗

### 标题

看影音 1.0.8 正式版

### 正文

弹窗先概括本次海报网络改善，再完整显示用户指定的网络说明，最后说明功能边界和原文件安全承诺。

- 本地媒体库、个人网盘和手动匹配候选使用统一的 TMDB 海报网络设置。
- 改善 TMDB 海报的网络连接。部分网络可以正常获取影片资料，但无法直接下载海报；遇到这种情况时，可保持 Clash Verge 等本机代理在后台运行，并选择能够访问 TMDB 图片的节点。关闭系统代理不影响已经运行的本机代理，但完全退出代理软件后，海报可能再次无法加载。
- 海报暂时下载失败时，已经获取的标题、简介、评分和季集信息会继续保留，不影响媒体扫描和播放。
- 本次更新不会修改、删除、改名或移动本地及个人网盘中的原始视频和字幕。

用户指定的第三条说明必须原样同步到 `UPDATE_DIALOG_COPY.md`、`RELEASE_NOTES.md` 和 Windows 当前版本历史，不得拆分或改写。

## 文档与版本同步

正式版实施时同步更新：

- `pubspec.yaml`：Windows 应用版本和历史 MSIX 兼容版本。
- `lib/core/app_version.dart`：当前 Windows 应用版本。
- `UPDATE_DIALOG_COPY.md`：Windows 1.0.8 正式版弹窗；Android 章节继续保留 1.0.4，不宣称本轮打包。
- `RELEASE_NOTES.md`：新增 Windows 1.0.8 正式版说明，保留 2.1.158 测试版历史。
- `lib/utils/version_history.dart`：新增 Windows 1.0.8 正式版历史；Android 当前平台仍映射到 1.0.4。
- `README.md`：Windows 当前版本和下载链接更新为 1.0.8；Android 下载仍指向已有 1.0.4 资产。
- 版本契约测试：同步 Windows 1.0.8、构建号 10008、Android 1.0.4 和仅 Windows 发布范围。

## 验证与构建

实施完成后必须验证：

1. 完整 `flutter test --no-pub` 通过。
2. `flutter analyze --no-pub` 无问题。
3. Windows Release 构建成功，`kanyingyin.exe` 产品版本为 1.0.8。
4. Inno Setup EXE 构建成功，安装器版本为 1.0.8，并复制到当前用户桌面。
5. 记录 EXE 文件大小、SHA-256 和 Authenticode 状态。
6. 构建前后均不运行 Android 手机或 Android TV 打包脚本。
7. Release 资产目录只包含 `KanYingYin-1.0.8.exe`，不得包含 APK、AAB 或 TV 产物。
8. 不自动安装新 EXE；如用户以后要求安装，再重新检查安装后的产品版本。

## GitHub 发布

验证通过后：

1. 将本地正式版改动提交并推送到 GitHub `main`。
2. 创建并推送带注释标签 `v1.0.8`。
3. 创建正式 Release `看影音 1.0.8 正式版`。
4. 只上传 `KanYingYin-1.0.8.exe`。
5. 对比 GitHub 资产大小和 SHA-256，完全一致后再公开 Release 并设为最新版。
6. 最后核对远端 `main`、`v1.0.8`、公开 Release 和本地工作区状态。

## 验收边界

- 不修改或删除本地与个人网盘原始视频和字幕。
- 不宣称 Windows EXE 已签名，除非 Authenticode 验证结果确实有效。
- 不宣称 Android 已重新构建或完成真机验收。
- 不构建、不发布、不上传 Android TV。
- 不删除本地已有的历史 Android 或 TV 构建文件，但不得将它们复制到本次 Release 资产目录。
