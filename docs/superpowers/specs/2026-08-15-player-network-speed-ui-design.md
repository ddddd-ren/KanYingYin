# 播放器网速显示与低速提示隐藏设计

## 背景

播放器已经从网盘分段中转会话获得实时 `CloudRangeRelayStatus`，顶部状态提示也能显示读取速度和缓存时长。当前低速提示由 `VideoPage` 以不可交互的状态块显示，进入低速状态后无法由用户关闭；播放器控制栏也没有持续可见的网速文字。

本轮为 Windows 和手机版 Android 增加统一的网速展示，并允许用户只对当前视频隐藏低速提示。交付版本为测试版 `2.1.160+20160`。

## 目标

- “当前网盘读取速度不足”提示右侧提供关闭按钮。
- 关闭低速提示后，本视频后续不再显示该提示；切换视频后自动恢复。
- 在播放器进度条正下方显示 `网速 4.3 MB/s`。
- 网速随播放器控制栏一起显示和隐藏。
- Windows 与手机版 Android 使用一致的数据、格式和视觉层级。
- 完成 Windows 测试版 EXE 与 Android 手机版 APK/AAB 的构建和独立验证。

## 非目标

- 不改变网盘读取、预缓冲、并发、重连或缓存调度逻辑。
- 不增加本地文件读取速度、系统总网速或其他网络诊断数据。
- 不增加永久关闭低速提示的设置项。
- 不改变播放器现有控件顺序、动画时长、动画曲线或主要点击区域。
- 不构建、测试或交付 Android TV 产物。
- 不自动安装测试版，不推送远端，不创建 GitHub Release。

## 已确认的方案

### 视觉方案

采用“A · 独立左对齐信息行”：网速文字位于进度条正下方，控制按钮位于下一行。该方案比将网速挤入按钮行更适合手机版横屏，也比右对齐更容易与播放状态建立视觉联系。

### 技术方案

新增纯展示器 `PlayerNetworkSpeedPresenter`，由完整控制栏与紧凑控制栏共同使用。两套控制栏通过现有 `IVideoPageController.relayStatus` 读取网盘中转状态，并在调用边界提取 `double? bytesPerSecond` 交给展示器，不让播放器依赖 `LocalVideoController`，也不在两套控制栏内重复格式化逻辑。

不采用以下方案：

- 直接复用 `pages/video` 下的 `CloudRelayStatusPresenter`，因为这会让播放器反向依赖视频页面模块。
- 在两套控制栏分别格式化速度，因为重复实现容易造成单位、精度和异常值处理不一致。

## 组件与数据边界

### `PlayerNetworkSpeedPresenter`

位置为 `lib/features/player/presentation/player_network_speed_presenter.dart`。

职责：

- 接收 `double? bytesPerSecond`。
- 对有限且大于零的数值使用 `1024 * 1024` 换算为 MB/s。
- 固定保留一位小数并输出 `网速 4.3 MB/s`。
- 速度为空、为零、负数、`NaN`、正负无穷时返回空，不显示占位。

展示器不持有状态，不读取 Modular，不判断平台，也不参与网盘调度。

### 顶部网盘状态提示

`CloudRelayStatusPresentation` 增加明确的 `dismissible` 展示属性。只有低速状态将该属性设为 `true`；连接中、预缓冲、就绪、重新连接和失败状态均为 `false`。

`VideoPage` 保留现有状态文案、颜色、圆角、位置以及正常就绪后五秒自动隐藏的逻辑。低速提示内部改为文字与小型关闭按钮组成的横向布局，关闭按钮语义为“隐藏本视频低速提示”。

### 播放器控制栏

完整控制栏和紧凑控制栏继续通过 `IVideoPageController` 读取 `relayStatus`，在调用边界提取 `relayStatus?.bytesPerSecond`，再调用 `PlayerNetworkSpeedPresenter`。本地播放没有网盘中转状态，因此不显示网速，也不显示 `0 MB/s`。

## 数据流

```text
网盘分段中转会话
  -> LocalVideoController.relayStatus（Observable）
    -> IVideoPageController.relayStatus
      -> CloudRelayStatusPresenter -> 顶部状态提示
      -> 调用边界提取 bytesPerSecond -> PlayerNetworkSpeedPresenter -> 完整/紧凑控制栏网速行
```

两种展示共享同一份实时状态，但各自负责不同信息层级：顶部提示表达连接、缓冲、低速和失败；控制栏只表达当前读取速度。

## 低速提示隐藏规则

`VideoPage` 使用独立的手动关闭状态，不复用现有 `_relayStatusHidden` 自动隐藏状态，避免低速与稳定状态转换时互相覆盖。

- 当前视频优先使用 `LocalVideoController.currentPlaybackHistoryKey` 作为稳定播放标识。
- 点击关闭按钮后，记录被关闭的播放标识。
- 同一标识后续再次进入低速状态时不显示低速提示。
- 播放标识变化后，旧记录自然失效，新视频可以再次显示低速提示。
- 若初始化瞬间尚无播放标识，关闭状态只绑定当前页面播放会话，并在 `changeEpisode` 成功切换目标时重置。
- 手动关闭只屏蔽 `dismissible == true` 的低速提示。重新连接和读取失败等重要状态仍可显示。
- 正常就绪提示原有五秒自动隐藏行为不变。

关闭按钮只改变展示状态，不暂停播放、不改变控制栏显示、不修改缓存或中转会话。

## 布局与样式

### 完整控制栏

在现有进度条与按钮行之间插入左对齐网速行：

- 与进度条共用 `10px` 水平内边距。
- 字号 `12px`，使用等宽数字特性。
- 使用白色弱化透明度，不增加图标、背景块或独立动画。
- 无有效网速时整行不占空间。

### 紧凑控制栏

保持外层按钮横向布局，将原先只承载进度条的 `Expanded` 区域改为小型纵向区域：上方为原进度条，下方为左对齐网速文字。播放、时间、字幕、全屏等控件仍保持原有顺序和交互。

### 可见性

网速行位于控制栏现有的 `Visibility` 和滑入滑出动画内部，因此控制栏收起、锁定或按现有画中画布局隐藏时同步隐藏，不引入单独计时器或动画。

## 异常与边界处理

- 无中转状态：不显示网速。
- 无效速度：不显示网速，避免出现 `NaN MB/s`、`Infinity MB/s` 或负数。
- 网盘状态重连：保留当前视频的低速关闭状态，但显示重连提示。
- 网盘读取失败：显示失败提示，不受低速关闭状态影响。
- 切集失败：仍属于原视频，不提前恢复低速提示。
- 切集成功：新播放标识生效；无标识回退状态同时重置。

## 测试策略

实施遵循测试先行：先写失败测试并确认失败原因，再写最小实现。

### 单元测试

- 正常速度格式化为一位小数。
- 空状态、零、负数、`NaN` 和无穷速度返回空。
- 低速展示可关闭，其他状态不可被低速关闭记录屏蔽。
- 同一播放标识保持隐藏，切换标识后恢复。

### 展示与契约测试

- 顶部低速提示具有关闭按钮和辅助功能语义。
- 正常连接、重连和失败提示没有低速关闭按钮。
- 完整控制栏与紧凑控制栏均接入共享展示器。
- 本地播放或无有效速度时不产生网速文字。
- 控制栏原有动画、进度拖动和按钮顺序契约保持不变。

### 工程验证

- 运行相关定向测试。
- 运行完整 `flutter test`。
- 运行 `flutter analyze`，不得出现错误。
- 构建 Windows Release。
- 构建 Android `mobile` APK/AAB；不运行 TV 流程。

自动化验证不能替代可见界面验收。实机验收需要分别确认 Windows 与手机版 Android 横屏下的网速位置、控制栏同步收放、关闭按钮命中范围，以及切换视频后低速提示恢复。

## 验收标准

- 网盘播放且速度有效时，进度条下方显示 `网速 x.x MB/s`。
- 本地播放和无效速度不显示网速行。
- 网速随控制栏同步显示和隐藏。
- 点击低速提示关闭按钮后，本视频不再显示低速提示。
- 同一视频重连或再次低速不会恢复低速提示，但重连和失败状态仍能显示。
- 切换到其他视频后，低速提示可以再次出现。
- Windows 与手机版 Android 的完整和紧凑控制栏均符合已确认的 A 布局。
- 定向测试、完整测试、静态分析、Windows Release 和 Android mobile 构建通过。
- Windows EXE、Android APK/AAB 的版本、签名、内容和桌面副本完成独立验证。
- Android TV 没有构建、测试或交付产物。
