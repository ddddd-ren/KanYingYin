# 网盘海报即时显示设计

## 背景

网盘资源完成 TMDB 刮削后，海报文件已经写入看影音的网盘海报缓存，持久化记录中也保存了 `posterCachePath`。但扫描、刷新、刮削状态变化或重新进入其他媒体界面时，部分网盘海报会重新进入异步加载与解码过程，短暂显示白色封面。

本机现状验证显示，网盘海报缓存目录中 JPG 文件与 URL 元数据文件一一对应，说明主要问题不是每次重新刮削，而是不同界面没有统一维持缓存海报的展示状态，以及部分页面状态变化会销毁并重建整片海报子树。

## 目标

- 正确刮削并成功缓存的网盘海报，在所有网盘资源展示界面优先使用本地缓存。
- 扫描、刷新、刮削进度和无新增资源的后台更新不得让未变化海报重新加载。
- 只有海报缓存路径或远程海报地址实际变化的资源才替换当前海报。
- 首次显示、缓存解码、网络回退和失败状态均不得露出白色封面。
- 本地资源现有海报逻辑和交互保持不变。

## 覆盖范围

统一行为覆盖所有能够展示网盘资源海报的界面，包括：

- 网盘媒体库海报墙。
- 电影、电视剧和动漫等统一分类页中的网盘资源。
- 网盘季度、选集和详情界面。
- 观看历史等包含网盘媒体的界面。
- 后续新增且使用统一网盘海报组件的展示入口。

不改变 TMDB 匹配策略、网盘扫描规则、媒体分组规则、原始网盘文件及本地资源海报行为。

## 根因

当前问题由三类行为叠加产生：

1. 网盘媒体库在扫描或刮削状态行出现、消失时，会改变 `Column` 的无 Key 子项位置。Flutter 可能销毁并重建后面的海报墙，导致全部图片重新进入首帧解码。
2. 各界面分别实现 `Image.file` 与网络回退。部分本地缓存图片没有首帧承接，网络组件也并非所有调用点都提供加载占位，因此透明图片区域会露出页面白底。
3. 页面重新进入或媒体库刷新时缺少统一的网盘海报预热与稳定身份策略。即使文件已经落盘，当前界面仍可能逐张等待异步解码。

## 方案比较

### 方案一：统一组件、缓存预热和稳定生命周期

建立统一网盘海报展示组件，集中处理本地缓存优先、远程回退、首帧占位、旧画面保留和稳定图片身份。媒体库初始化后仅预热即将显示的本地网盘海报；各页面使用稳定 Key，状态行变化不得销毁海报墙。

优点是从共同边界解决问题，新入口可以自动复用一致行为；内存和网络行为可以集中控制。缺点是需要迁移多个现有调用点。

### 方案二：逐页面补丁

分别给网盘媒体库、分类页、历史页和选集页添加 `frameBuilder`、占位图和 Key。

改动分散且容易遗漏，后续页面仍可能复发，因此不采用。

### 方案三：扩大 Flutter 全局图片缓存

通过提高全局 `ImageCache` 数量和字节上限，降低图片被逐出的概率。

该方案不能修复子树重建或无效缓存路径，还会不可控地增加内存占用，因此不采用。

## 详细设计

### 统一网盘海报组件

新增一个只负责网盘海报呈现的共享组件。输入至少包含本地缓存路径、远程海报地址、显示尺寸策略和占位构建器。

组件按以下顺序选择图像：

1. `posterCachePath` 非空且文件存在时使用本地文件。
2. 本地缓存不存在或解码失败时，使用统一 TMDB 图片客户端加载远程地址。
3. 两者都不可用或加载失败时显示统一媒体占位。

组件以规范化后的缓存路径和远程地址作为图片身份。父组件重建但身份未变化时，不重新创建加载任务；身份变化时，在新图片首帧可用前保留旧的成功画面。没有旧画面时显示统一媒体占位，不能显示透明或纯白区域。

### 缓存预热

媒体库完成索引和网盘 TMDB 记录加载后，收集当前界面即将展示且文件存在的网盘 `posterCachePath`，在网格显示前预解码首屏范围内的海报。

预热只读取本地文件，不访问 TMDB 网络，不重新刮削，也不修改缓存文件。预热数量按当前视口可见卡片数增加一行缓冲计算，避免一次解码整个媒体库而挤占图片缓存。用户滚动后仍由网格懒加载后续图片。

刷新时保留已经显示的网格；只预热新增或海报身份变化的项目，不让未变化卡片退回占位。

### 页面生命周期

网盘媒体库的扫描、批量刮削和自动整理进度区域使用稳定 Key，搜索栏和海报墙也使用固定 Key。进度区域插入或移除时，Flutter 必须移动并复用原海报墙元素，而不是销毁重建。

所有网盘海报卡片继续使用媒体稳定标识作为 Key。排序或筛选变化时通过 `findChildIndexCallback` 维持卡片状态；资源被删除、隐藏或真实分组身份变化时才销毁对应卡片。

分类页、观看历史、季度和选集界面只在资源属于网盘来源时使用统一网盘海报组件。本地资源继续走现有本地海报路径。

### 错误处理

- 缓存路径存在但文件缺失：直接尝试远程地址并显示占位，不删除元数据。
- 本地解码失败：保留旧成功画面；没有旧画面时显示占位，然后尝试远程地址。
- 远程加载失败：显示占位，不覆盖仍可用的旧缓存海报。
- 扫描或刮削失败：海报展示状态不受影响，原始网盘视频和字幕不做任何修改。

## 测试设计

### 共享组件测试

- 有效 `posterCachePath` 优先于远程地址，且不会调用网络加载器。
- 父组件重建且海报身份不变时，本地解码或网络加载只启动一次。
- 海报身份变化时，新首帧出现前保留旧海报。
- 本地文件缺失或解码失败时回退网络；网络失败时显示统一占位。
- 任意加载阶段都不存在白色空组件。

### 页面回归测试

- 网盘媒体库扫描开始和结束时，海报墙及未变化卡片的 State 身份保持不变。
- 无新增资源刷新时，已有网盘海报不重新加载。
- 单项或批量刮削只替换发生变化的卡片。
- 分类页、季度、选集和观看历史中的网盘海报使用本地缓存；本地资源原有组件不变。
- 排序、筛选和进度变化后，卡片稳定 Key 仍能正确映射资源。

- 运行相关 Flutter 单元与组件测试。
- 运行 `flutter test`。
- 运行 `flutter analyze`，要求无错误。
