# GitHub Windows 自动检查与更新设计

## 目标

为看影音 Windows 版增加基于项目官方 GitHub 仓库 `ddddd-ren/KanYingYin` 的正式版本检查与应用内更新能力。应用启动后每天静默检查一次，关于页提供不受每日节流限制的手动检查入口。发现更高的正式版本后，用户可以在应用内查看更新说明、下载安装程序、验证文件并启动交互式安装。

## 已确认的产品行为

- 仅在 Windows 桌面版启用，不改变 Android 手机版和已暂停的 Android TV 发布流程。
- 只接受 GitHub 中 `draft == false` 且 `prerelease == false` 的 Release。
- 启动进入主界面后每天自动检查一次；同一本地日期已有一次成功检查则跳过。
- 关于页提供“检查更新”入口，手动检查不受每日节流限制。
- 自动检查失败时不打扰用户；手动检查失败时明确提示。
- 本地版本等于远端最高正式版本时视为最新版本。
- 本地测试版高于远端最高正式版本时不提示降级。
- 发现新版本后显示版本号、发布时间和 GitHub Release 更新说明。
- 用户明确选择“下载并更新”后才下载，不静默安装。
- 下载完成并通过完整性校验后启动可见的 Inno Setup 安装程序，然后退出看影音。

## 方案选择

采用“应用内检查、下载并启动安装器”。不采用只打开浏览器的方案，因为它没有完成应用内更新；也不采用独立静默更新器，因为当前安装包没有代码签名，额外的后台进程、回滚与静默安装会显著扩大风险和维护范围。

## 架构

新增 `lib/features/app_update/` 功能目录，按领域、数据、应用和表现职责拆分。启动页与关于页只调用更新协调器，不直接解析 GitHub 响应、比较版本或处理文件。

### 领域层

领域层包含严格的三段语义版本类型，以及正式 Release、Windows 安装包等不可变模型。

- 仅接受 `v主版本.次版本.补丁版本` 标签。
- 三段均为非负整数，按数值依次比较，不使用字符串排序。
- 无效标签被忽略，不能导致整个检查失败。
- 本地版本从 `AppVersion.current` 读取，并使用同一解析器。

### 数据层

GitHub 客户端使用 Dio 请求官方 API：

`https://api.github.com/repos/ddddd-ren/KanYingYin/releases?per_page=30`

请求设置 GitHub JSON `Accept` 头、固定的 `User-Agent` 和有限的连接、接收超时。客户端过滤草稿、预发布和无效标签，再按语义版本选择最高正式版；不依赖 Release 发布时间决定版本高低。

Windows 安装包选择规则：

- 文件扩展名必须是 `.exe`。
- 文件名必须包含所选 Release 的完整版本号。
- 候选必须唯一；没有候选或存在多个候选都视为该 Release 不可更新。
- GitHub 资产必须提供合法的 `sha256:<64 位十六进制>` 摘要。
- 保存资产大小、摘要和 `browser_download_url`，供下载阶段复核。

数据层只使用 GitHub 官方 API 和资产下载地址，不引入第三方镜像或自建更新服务器。

### 应用层

应用层包含检查协调器、下载器与安装器启动端口。

检查协调器返回明确结果：发现更新、已经最新、本地版本更高、平台不支持、检查失败。表现层根据自动或手动触发决定是否反馈，避免用异常控制界面行为。

每日节流只记录“上次成功检查的本地日期”。请求失败、响应无效或找不到可用安装包时不写入成功日期，以便下次启动重试。一次成功的手动检查同样更新日期，避免同一天重复自动请求。

下载器将安装包写到系统临时目录中的版本专属临时文件。下载流程依次验证：

1. HTTP 请求成功；
2. 实际文件长度等于 GitHub 资产大小；
3. 文件 SHA-256 等于 GitHub 资产摘要。

任一校验失败都删除临时文件，不允许进入安装步骤。已经存在的同版本文件只有重新通过大小和摘要校验后才能复用。

安装器启动通过可替换端口实现。生产实现以独立进程启动安装器；只有启动成功后才退出看影音，启动失败则保留应用并提示用户。Inno Setup 继续使用现有可见向导和 `CloseApplications=yes`，不增加静默参数。

### 表现层

更新弹窗包含：

- 最新正式版本号和发布时间；
- GitHub Release 更新说明，按纯文本安全展示，不解析或执行 HTML；
- “稍后提醒”和“下载并更新”操作；
- 下载阶段的进度、已下载大小和总大小；
- 失败后的可理解错误信息与重试入口。

下载期间禁止重复提交，弹窗不可通过遮罩误关闭。用户选择“稍后提醒”不会永久忽略版本，下次成功通过每日检查条件后仍可提醒。

关于页新增“检查更新”设置项。手动检查期间显示检查状态；无更新时提示“当前已是最新正式版”，本地测试版更高时提示“当前为高于正式版的测试版本”，失败时提示“检查更新失败，请稍后重试”。

## 启动流程

`InitPage` 在现有初始化、快捷方式检查和默认页导航完成后，先处理本地版本更新说明。`_showVersionChangelog` 改为可等待的异步流程，确保用户关闭本地说明后才开始远端自动检查，避免两个全局弹窗重叠。

远端检查仅在 Windows 桌面壳运行。检查发现更新时才显示弹窗；最新版本、本地版本更高、当日已检查和自动检查失败均保持静默。

## 依赖注入与可测试性

更新客户端、更新协调器、下载器和安装器启动端口通过 Flutter Modular 注册。网络客户端、时钟、设置存储、临时目录、文件启动与应用退出均可注入，从而在测试中使用确定输入，不访问真实 GitHub、不运行安装器也不退出测试进程。

不新增 `package_info_plus`。项目继续以 `AppVersion.current` 作为运行时版本事实，并由现有版本一致性测试保证它与 `pubspec.yaml` 同步。

## 错误处理

- GitHub 超时、断网、限流和非成功状态：自动检查静默，手动检查提示失败并记录诊断日志。
- GitHub JSON 字段缺失或类型错误：忽略无效 Release；无法得到有效正式版时按检查失败处理。
- 没有唯一 Windows EXE 或缺少合法摘要：不提供更新，记录拒绝原因。
- 下载中断：关闭文件句柄并删除不完整文件，可由用户重试。
- 大小或摘要不一致：删除文件并明确提示“安装包校验失败”。
- 安装器无法启动：保留已运行的应用，提示失败，不调用退出。

日志不得记录用户凭据、GitHub 令牌或响应中的敏感请求头。本功能访问公开仓库，无需内置 GitHub Token。

## 测试策略

按照测试驱动开发逐项覆盖：

- 三段语义版本解析、数值比较和无效标签。
- 草稿、预发布和无效版本过滤，以及语义最高正式版选择。
- 唯一 Windows EXE 选择、版本文件名约束和 SHA-256 摘要解析。
- 已是最新版、本地测试版更高、发现更新和网络失败结果。
- 每日成功检查节流、失败不节流、手动检查绕过节流。
- 下载进度、已有文件复核、大小不符、摘要不符和失败文件清理。
- 安装器启动成功后退出、启动失败不退出。
- 更新弹窗按钮、更新说明、进度、错误与重试状态。
- 启动页先等待本地更新说明，再调用远端检查。
- 关于页手动检查入口及各类反馈。

完成实现后执行完整 `flutter test`、`flutter analyze` 和 Windows Release 构建。进入可交付迭代时，按项目发布约束核对已安装版本，更新 `pubspec.yaml`、`AppVersion.current`、`RELEASE_NOTES.md`、`UPDATE_DIALOG_COPY.md`、`version_history.dart` 及版本契约，生成并验证 Inno Setup EXE，复制到桌面。Android TV 产物仍不得生成。

## 非目标

- 不自动更新 Android 手机版或 Android TV。
- 不检测 GitHub 草稿、预发布或分支提交。
- 不支持降级、跳版本选择、后台静默安装或自动回滚。
- 不新增常驻更新进程、自建更新服务或第三方下载镜像。
- 不改变 GitHub Release 的发布权限和凭据管理。

## 验收标准

1. Windows 应用启动后每天至多执行一次成功的自动检查，失败可在后续启动重试。
2. 关于页可随时手动检查正式版本。
3. 仅比本地版本更高的 GitHub 正式 Release 会触发更新弹窗。
4. 用户可查看更新说明和下载进度，也可选择稍后更新。
5. 只有大小及 SHA-256 都匹配的安装包才能启动。
6. 安装器启动成功后应用退出；启动失败时应用保持运行并反馈。
7. 自动网络失败不打扰用户，手动失败有明确反馈。
8. 原有本地版本更新说明与远端更新弹窗不会重叠。
9. 自动化测试、静态分析和 Windows Release 构建通过。
