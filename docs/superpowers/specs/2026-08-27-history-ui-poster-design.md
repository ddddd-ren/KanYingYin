# 观看历史界面与海报修复设计

## 目标

- 保留按观看时间排列的单集时间线，并按“今天、昨天、更早”分组。
- 每条记录使用 `60 × 90` 的 2:3 海报，标题统一为“剧名 · 第 N 集 集名”。
- 海报信息短暂缺失时不覆盖已有有效海报；旧记录缺图时可复用同来源、同剧集的有效海报。
- 不修改或删除用户的视频、网盘文件、媒体索引和既有观看进度。

## 界面

- 沿用“继续观看 / 全部历史”筛选和日期分组。
- 每条记录从左到右为海报、内容、删除按钮。
- 内容依次显示规范化标题、来源/百分比/观看时间、已播时长/总时长和进度条。
- 标题最多两行；优先显示已有剧名、集号和可用集名，不直接展示 `.mkv` 等原始长文件名。
- 海报加载失败时保留统一占位图和可读标题，不阻塞继续播放、删除或清空历史。

## 海报数据流

1. 播放器生成新历史记录时，优先使用当前播放目标携带的海报。
2. 当前目标缺少海报时，从同一播放列表中的有效剧集海报补齐。
3. 更新同一条历史时，新记录缺少海报不得覆盖旧记录中的有效地址或缓存路径。
4. 历史页显示旧记录时，可从同来源、同剧名的其他历史记录中选择有效海报作为兜底。
5. 不新增历史迁移任务，不主动访问网络补图；仍由现有 `CloudPosterImage`、`PosterCover` 和 TMDB 图片客户端负责缓存、网络加载与失败占位。

## 修改边界

- 优先修改观看历史页面、历史记录合并逻辑及其测试。
- 复用现有海报组件和标题识别能力，不新增依赖、设计系统或通用抽象。
- 保留工作区已有修改，不执行 Git commit。

## 验证

- 回归测试覆盖：缺海报的新进度不会清空旧海报；同剧旧记录可在页面获得海报兜底；标题不显示原始视频扩展名；A 布局关键结构保持存在。
- 运行相关 Flutter 测试、`flutter analyze` 和 Windows Release 构建。
- 通过截图或页面实机检查海报比例、标题截断、分组、进度条和缺图占位。
