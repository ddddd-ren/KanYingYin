# 让标签分类库复用媒体库成品数据

本文定义标签分类库的数据边界。标签分类库只读取本地媒体库和网盘媒体库已经生成的作品结果，再按电影、动漫和电视剧分类，不扫描来源、不重新归并作品，也不调用 TMDB。

## 文档计划

- **类型**：设计规格
- **目标**：统一标签分类库与两个来源媒体库的作品展示结果
- **受众**：负责媒体库、网盘资源和分类入口的开发人员
- **内容**：现状、方案选择、数据流、刷新边界、失败处理和验证要求
- **待确认项**：无

## 现状与根因

标签分类库当前在 `MediaCategoryRuntime.library` 中读取本地和网盘索引项，再调用 `CloudMediaLibraryAggregator` 生成作品。网盘媒体库则使用 `CloudResourceCollectionGrouper` 生成 `CloudResourceMediaGroup`，因此两个页面拥有不同的作品归并入口。

`LocalController.combinedMediaLibrary` 不能直接解决问题。它也会调用 `CloudMediaLibraryAggregator`，没有复用网盘媒体库已经确定的作品、季度、隐藏状态和手动匹配结果。

两套归并入口可能产生以下差异：

- 同一作品的分组数量不同
- 标题、海报和简介来源不同
- 电视剧季度和特别篇归属不同
- 隐藏资源在两个页面中的可见性不同
- 手动匹配或自定义标题只在一个页面生效

## 目标与非目标

本次调整让标签分类库成为媒体库的只读分类视图。

目标包括：

- 分类库作品来自本地媒体库和网盘媒体库的成品结果
- 同一资源在来源媒体库和分类库中保持相同身份、标题、海报和剧集
- 分类刷新不连接文件来源，也不调用 The Movie Database（TMDB）
- 来源媒体库更新后，分类库读取新的成品快照
- TMDB 不可用时，分类、扫描和播放继续使用已有资料

本次不包含：

- 新增数据库表或分类专用缓存
- 新增文件监听、后台轮询或定时扫描
- 修改本地文件或网盘文件
- 改写现有 TMDB 匹配规则
- 同时保留两套作品归并逻辑

## 方案选择

采用“共享成品媒体目录”方案。本地媒体库和网盘媒体库输出统一的 `MediaLibrarySeries` 快照，标签分类库只合并和筛选这些快照。

未采用以下方案：

- **继续修补 `CloudMediaLibraryAggregator`**：仍会保留第二套网盘作品归并入口，后续规则变化可能再次产生差异
- **持久化分类结果**：会增加同步、失效和迁移成本，现阶段没有独立持久化的必要

## 统一数据契约

每个来源媒体库输出不可变的 `MediaLibrarySeries` 列表。该列表代表来源页面最终展示的作品，不代表扫描器产生的原始文件项。

每个作品必须保留以下数据：

- `key` 和 `seriesKey`
- 来源类型、来源 ID 和来源名称
- 展示标题、媒体类型和类型标签
- TMDB 标题、简介、评分、发布日期和图片
- 海报缓存路径
- 已按来源媒体库规则排序的剧集列表
- 本地路径或网盘远程 ID、路径和字幕引用
- 当前可用状态

网盘媒体库将每个 `CloudResourceMediaGroup` 一对一转换为 `MediaLibrarySeries`。转换只复制已经确定的作品和剧集字段，不再次解析文件名、不合并作品、不查询 TMDB。

本地媒体库继续使用 `LocalController.localMediaLibrary.series`。分类库不得读取 `localLibraryItems` 或 `cloudLibraryItems` 后自行构建作品。

## 数据流

以下数据流取代分类库当前的重复聚合流程：

```text
本地扫描或手动刷新
  -> 本地媒体库生成 MediaLibrarySeries
  -> 更新本地成品快照

网盘扫描或手动刷新
  -> 网盘媒体库生成 CloudResourceMediaGroup
  -> 一对一转换为 MediaLibrarySeries
  -> 更新网盘成品快照

本地成品快照 + 网盘成品快照
  -> 合并为统一媒体目录
  -> MediaLibraryQuery 按来源、关键词和分类筛选
  -> 电影、动漫和电视剧页面
```

统一媒体目录只负责合并列表和生成来源筛选项。它不依赖扫描器、网盘客户端或 TMDB 客户端。

## 分类判定

`MediaLibraryQuery` 继续负责分类，不修改作品身份。分类判定只使用成品作品中的 `mediaType` 和 `genres`。

判定规则保持为：

- `mediaType == movie`：电影
- `mediaType == tv`：电视剧
- 类型标签包含动画、动漫、`animation` 或 `anime`：动漫

动漫电视剧可以同时出现在动漫和电视剧分类中。该行为沿用现有查询规则，不在本次调整中改变。

## 初始化与刷新

分类页初始化只加载统一媒体目录的最新已持久化快照。初始化不得调用本地目录扫描、网盘目录扫描、作品识别或 TMDB 请求。

“刷新分类”执行相同行为：

1. 重读本地媒体库成品快照
2. 重读所有已启用网盘来源的成品快照
3. 合并快照并更新分类页面

本地媒体库或网盘媒体库完成扫描后，应更新各自成品快照并通知统一媒体目录。分类页处于打开状态时刷新展示；未打开时在下次进入时读取最新快照。

## 隐藏、恢复与播放

分类库不维护第二套隐藏状态。用户从分类页隐藏网盘视频时，操作委托给网盘媒体库现有隐藏服务，成功后由网盘成品快照移除该视频。

播放继续使用成品快照中的 `MediaLibraryEpisode`：

- 本地播放使用已保存的本地路径、字幕路径和同作品播放列表
- 网盘播放使用来源 ID、远程 ID、远程路径、字幕引用和季集信息

隐藏或播放失败时保留当前快照。分类库显示错误，但不删除资源，也不伪造成功状态。

## 失败处理

分类库读取失败时遵守以下规则：

- 一个来源失败时保留该来源上次可用快照
- 首次读取失败且没有快照时，只隐藏失败来源的内容并显示可重试提示
- TMDB 无 Key、断网或服务不可用时继续展示已有媒体库资料
- 来源正在扫描时继续展示上次完成的快照，不读取部分扫描结果
- 快照更新只在来源媒体库完成一次有效提交后生效

## 实现边界

优先复用现有模型和分组器，不新增持久化仓储。预计调整以下位置：

- `lib/features/library/application/media_category_runtime.dart`
- `lib/pages/cloud/resources/cloud_resources_controller.dart` 或其现有成品集合出口
- `lib/pages/cloud/resources/cloud_resource_collection.dart` 的一对一转换位置
- `lib/pages/local/local_controller.dart` 的统一快照出口
- 对应的分类页、网盘集合和控制器测试

`MediaCategoryRuntime` 应删除以下职责：

- 读取 `CloudWorkTmdbRepository`
- 读取原始本地和网盘索引项
- 调用 `CloudMediaLibraryAggregator` 重新生成作品
- 维护分类专用的网盘隐藏状态副本

若现有控制器能够直接提供成品快照，不新增接口层、事件总线或缓存管理器。

## 验证要求

自动化测试必须覆盖：

1. 来源媒体库与分类库拥有完全相同的作品 `key`
2. 标题、海报、媒体类型、季度和剧集顺序保持一致
3. 分类页初始化和“刷新分类”不会调用扫描器或 TMDB
4. 网盘隐藏和恢复会同步更新分类结果
5. 来源扫描提交新快照后，分类页显示新增、删除和改名结果
6. 一个来源读取失败时，其他来源和上次快照仍可使用
7. 电影、动漫和电视剧分类继续遵守现有交叉分类规则

实现完成后运行相关回归测试、完整 `flutter test`、`flutter analyze` 和 Windows Release 构建。进入版本交付阶段后，再单独更新版本、发布文案和安装包。
