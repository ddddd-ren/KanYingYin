# 媒体索引与 TMDB 刮削同步优化设计

## 背景

当前本地和网盘索引都能在扫描时发现文件新增、删除、重命名、大小及修改时间变化，但文件变化后的 TMDB 资料继承规则不一致：

- 本地文件重建索引项时不会完整继承旧 TMDB 身份、手动匹配来源、字段锁和缓存海报。
- 本地新增剧集需要再次进入网络刮削流程，即使同系列已有唯一且已确认的 TMDB 身份。
- 网盘作品级记录能通过稳定 `workKey` 继续生效，但重建后的索引项不一定立即持久化已有作品资料。
- 当作品键、根目录 ID 或路径改变时，部分场景缺少明确的安全迁移规则。

本设计优化现有扫描触发的增量同步，不引入实时文件监听或网盘定时轮询。

## 目标

1. 文件内容更新后同步文件属性，并按本设计的身份兼容规则保留 TMDB 绑定。
2. 文件改名或移动时，仅在身份唯一且无歧义时迁移刮削结果。
3. 新增剧集能够离线继承同作品已经确认的 TMDB 资料。
4. 网盘索引重建后，将现有作品级资料同步到新增或替换的索引项。
5. 任何冲突或识别失败都不得删除媒体文件、覆盖可信手动匹配或破坏上次可用索引。

## 非目标

- 不增加 `Directory.watch`、后台常驻服务或定时扫描。
- 不计算完整视频内容哈希。
- 不自动修改本地文件名、目录名或网盘远程资源。
- 不在普通文件扫描时刷新 TMDB 网站上的评分、文案或图片。
- 不新建另一套本地 TMDB 持久化仓储。

## 方案选择

采用现有索引和刮削仓储内的身份继承与安全迁移：

- 本地继续以 `LocalMediaIndexItem` 保存文件索引和 TMDB 状态。
- 网盘继续以 `CloudMediaIndexItem`、`CloudWorkTmdbRecord`、系列规则和逐视频规则保存状态。
- 扫描完成后先执行离线协调，再对剩余待匹配项运行现有自动刮削。

该方案不改变持久化格式，主要修改现有索引合并和刮削协调逻辑。

## 本地索引同步

### 同路径文件更新

当新旧索引项具有相同 `id` 时：

1. 新索引项提供当前大小、修改时间、媒体信息、字幕、封面候选和重新解析的季集信息。
2. 若解析后的系列、季、集身份与旧索引兼容，则继承：
   - `tmdb` 和 `tmdbIdentity`；
   - `scrapeStatus`、`tmdbMatchOrigin` 和 `tmdbRuleVersion`；
   - `titleLocked`、`posterLocked`、`overviewLocked`；
   - 新扫描没有得到可用封面时的旧缓存封面；
   - `manualOverride` 及其手动季集字段。
3. 若新旧逻辑身份冲突，则不继承 TMDB 状态，使用新解析结果并保持待匹配。

逻辑身份兼容规则：

- 两边都有季集号时，系列名、季号和集号必须一致。
- 两边都没有季集号时，规范化系列名必须一致。
- 一边有季集号而另一边没有时视为冲突。
- 手动覆盖项以旧的手动系列、季、集身份为准，不被自动解析覆盖。

### 改名和移动

扫描当前来源时，将未被路径命中的旧项作为迁移候选。新项只有满足以下全部条件才继承旧状态：

1. 旧路径已经不在本次扫描结果中。
2. 文件大小和修改时间完全一致。
3. 在当前来源中，新项和旧项之间形成唯一的一对一候选。
4. 不存在另一个相同大小和修改时间的旧项或新项。
5. 新旧两边都有时长和画面尺寸时，这些媒体信息也必须一致。

唯一候选允许文件名、父目录和解析标题发生变化，以覆盖正常改名和移动。存在重复副本或任何歧义时不迁移，避免把海报和 TMDB 身份绑定到错误视频。

### 新增剧集离线继承

本地扫描保存索引后、网络自动刮削前，按规范化系列名收集已匹配项目：

- 若已匹配项目只包含一个非空 `tmdbIdentity`，将其中最新的 TMDB 元数据同步给同系列待匹配项目。
- 匹配来源和字段锁只有在同系列已匹配项目保持一致时才继承。
- 若出现多个 `tmdbIdentity`、锁状态冲突或手动隔离项，则不自动继承。
- 继承后仍按新项目的季集号展示，不改变文件路径和播放身份。

离线继承不要求 TMDB Key，也不发送网络请求。剩余待匹配系列继续遵守现有自动刮削开关和 Key 要求。

## 网盘索引同步

### 文件变化检测

保留现有目录指纹字段：远程 ID、名称、规范化路径、文件类型、大小和修改时间。每次进入 Windows 网盘资源页、切换来源或手动刷新时执行扫描；未变化目录继续复用缓存。

### 已有作品资料回写

`CloudWorkTmdbCoordinator.loadAndSchedule` 加载作品树和已存记录后：

1. 对当前 `workKey` 已有且状态为 `matched` 的记录，复用 `CloudWorkTmdbService.syncRecordToIndex`。
2. 将 TMDB 标题、简介、评分、图片、类型标签和缓存路径写入该作品当前全部索引项。
3. 新增剧集因此不需要重新请求 TMDB，也能持久化已有作品资料。
4. 逐视频季集映射继续在索引扫描阶段应用，不被作品资料回写覆盖。

### 作品键变化迁移

当前 `workKey` 没有匹配记录时，只在以下条件下尝试迁移旧记录：

- 来源相同；
- 媒体类型兼容；
- 作品根远程 ID 相同，或规范化作品根路径相同；
- 候选记录最终只指向一个 TMDB 身份。

满足条件时迁移完整记录，并更新 `workKey`、作品根 ID 和路径。同一 TMDB 身份存在多条候选时优先手动记录，再选择 `checkedAt` 最新的记录；不删除旧兼容记录。候选包含不同 TMDB 身份时生成冲突记录，不自动选择。旧式单资源记录继续仅作为兼容迁移来源，不扩展新的双轨行为。

## 已知边界

- 同一路径和文件名被无关视频覆盖时，如果解析身份仍相同，系统在不读取完整内容哈希的前提下无法识别为另一部媒体；此时按同一逻辑媒体处理，用户可主动重新匹配。
- 改名或移动过程如果改变了文件修改时间，系统不会自动迁移旧绑定，后续由同系列离线继承或自动刮削处理。
- 网盘提供商同时更换作品根 ID 和路径时不会强行迁移，避免误绑定到另一份资源。

## TMDB 资料刷新边界

普通文件扫描只同步文件状态和已有绑定，不刷新 TMDB 上游资料。

- 当前规则版本下已匹配的自动记录继续复用。
- 手动匹配记录不参与自动替换。
- 用户主动执行重新匹配或强制刮削时才重新获取完整资料。
- 规则版本升级和缺少季度集名时继续使用现有补抓逻辑。

## 数据流

```text
本地或网盘扫描
  -> 生成当前文件索引
  -> 合并同路径可信状态
  -> 执行唯一改名/移动迁移
  -> 保存文件索引
  -> 离线同步已确认作品资料
  -> 对剩余项目按设置自动刮削
  -> 刷新媒体库展示
```

## 失败处理

- 扫描取消：不提交部分索引和目录指纹。
- 来源或目录读取失败：保留该范围上次可用索引，并报告失败路径。
- 身份迁移冲突：不覆盖旧记录，新项目保持待匹配。
- TMDB 同步失败：文件索引仍然成功，保留原始视频和播放能力。
- 仓储写入失败：不把内存状态报告为已经持久化。
- TMDB 不可用、无 Key 或断网：本地扫描、网盘扫描和播放继续可用。

## 可观测性

复用现有扫描结果与日志，不新增界面：

- 本地日志记录继承数量、迁移数量、冲突数量和待匹配数量。
- 网盘日志记录已有作品资料回写数量和迁移冲突。
- 日志只记录来源 ID、索引 ID 和计数，不记录凭据或访问令牌。

## 测试设计

### 本地

1. 同路径内容更新且逻辑身份不变时保留手动 TMDB、字段锁和缓存海报。
2. 同路径文件变成其他逻辑媒体时清除旧 TMDB 并进入待匹配。
3. 唯一改名或移动候选继承旧状态。
4. 相同大小和修改时间存在多个候选时不迁移。
5. 新增剧集在无 Key 时继承唯一的同系列 TMDB 身份。
6. 同系列存在多个 TMDB 身份时不自动继承。

### 网盘

1. 新增剧集扫描后离线继承并持久化作品级 TMDB 资料。
2. 同一作品内容替换后更新大小和修改时间并保留作品资料。
3. 根 ID 或路径唯一对应时迁移作品记录。
4. 多个旧身份冲突时不自动迁移。
5. 逐视频手动季集映射在作品资料回写后仍然有效。
6. 部分目录扫描失败时保留失败子树缓存。

### 验证门槛

- 相关索引、TMDB、网盘协调器回归测试通过。
- 完整 `flutter test` 通过。
- `flutter analyze` 无错误。
- Windows Release 构建通过。
- 实机确认本地改名、内容替换、网盘新增剧集和断网继承。
