对比对象为本轮开始时的 2.1.241 工作区和完成优化的 2.1.242 测试版。改前保留了当时尚未提交的改动。两版均使用 Flutter 3.41.9 和各自版本的 Windows 原生运行器。

附包包含 12 个正式进程的逐次点击、帧时序、统计脚本、独立连点采样、窗口截图、分类基准和安装包核验记录。Profile 首进切片保留事件名称、时间和帧号，省略额外事件参数。[下载测量数据 ZIP](2026-11-19-navigation-samples.zip)

## 测量方法

- 同一台 Windows 11 电脑，Core i9-13980HX、GeForce RTX 4060 Laptop GPU、240 Hz 显示器，系统缩放 150%。窗口客户区为 1904 × 1281 物理像素。
- 两档样本分别有 1,000 和 10,000 部作品。电影、动漫和电视剧各约占三分之一，每条索引指向一个可播放的绿色 H.264 MP4。两版复用相同的索引、视频和设置，打开应用前复制独立的 Hive 目录。应用每轮重新启动，系统文件缓存保留。测试数据不含网络海报或真实网盘账号。
- Windows 驱动程序向 Flutter 窗口发送鼠标消息，核对实际收到事件的目标标签。首页可见取首页完成布局且窗口可见的时刻。首次交互取进程启动至首次实际处理导航点击的时刻，包含驱动程序取得按钮坐标的等待，属于可交互时间的观测上界。
- 切页计时从投递点击开始，到目标页第一张可点击卡片所在帧完成光栅化为止。另记点击到导航回调的用时。首进顺序是电影、动漫、电视剧，随后回到电影，再依次切换三个标签。流程中每次都核对目标页。
- 帧统计区间从第一次分类点击到点击播放前。分别计算 UI 构建和光栅耗时的 P95。两阶段任一超过预算即记为超时帧。16.67 毫秒对应 60 Hz，4.17 毫秒对应这台显示器的 240 Hz。
- 常规对比在同一登录会话的独立 Win32 桌面运行。视频插件回报首帧纹理和窗口实际出现绿色画面分别记录。Windows 对非活动桌面的窗口截图有限制，实际画面验证单列。

## 快速连点

千条片库预热后，单独向窗口连续投递「电影 → 电视剧 → 动漫」三个点击。两版各跑一轮，实测相邻间隔约 40 毫秒，实际收到的索引、最终页和一秒后的首卡均已核对。从最后点「动漫」到首卡完成光栅化，2.1.241 为 **1,116.59 毫秒**，2.1.242 为 **18.88 毫秒**。

## 播放出画与全屏

- 在普通播放设置下做了活动桌面补测。两版都用千条片库。第一对窗口未取得前台焦点，从点击后上次还未看到绿色到首次看到绿色，旧版为 **1,973～2,024 毫秒**，新版为 **678～736 毫秒**。两次首个绿色样本中都有 91.5% 的采样像素命中。第二对窗口均处于前台，分别为 1,669～1,725 毫秒和 553～615 毫秒。两档首帧纹理数据来自上表的三轮常规流程。
- 新版开启 Anime4K 效率档时，mpv 回读了 6 个已启用的非空着色器文件，硬件解码为 `d3d11va-copy`。播放器读取到测试字幕轨及对应正文。用绿色视频实测全屏进出，窗口到达显示器完整边界 2560 × 1600 并稳定至少 180 毫秒，退出后恢复原来的位置和大小。
- 在另一组两集样本中，第一集仍在播放时点击右侧选集面板的第二集。播放器从绿色的 S01E01 切换到品红色的 S01E02，窗口截图同时确认了标题和画面。字幕另有实际显示英文测试正文的窗口截图。
- 单独用 Profile 模式采集首进电影页的虚拟机时间线，两份首进轨迹分别有 12,911 和 10,249 条事件。表中的延迟和帧数全部取自 Release。

## 本轮改动

- 启动先完成存储路径选择、待处理迁移和设置读取，直接建立用户选择的首页。首页完成首帧后，再处理快捷方式、版本说明和自动更新，Anime4K 在空闲时准备，首次启用也会等待同一个准备任务。
- 顶层标签改用现有导航库的公开路由接口，取消原先连续点击间的 500 毫秒等待。最后一次点击决定目的页，离开的模块仍会释放。首次提示遇到播放器等页面会等待合适时机继续。
- 分类页复用片库快照。文件和来源可用性异步核验，媒体变化或刷新会更新结果，播放前会确认目标文件。旧索引按需更新，大片库分组跳过已知属于其他作品的候选。

## 分类业务基准

另一组 Flutter 测试用真实文件和正式控制器隔离测量「取得整份可见作品列表」的时间。首次运行读库，随后连续五次进入取中位数。两版每次都检查作品数量和样本摘要。这项结果不包含 Windows 输入、GPU 帧和显示器刷新。[复测命令](../../tool/performance/README.md)

| 耗时（毫秒） | 1,000 部改前 | 1,000 部改后 | 10,000 部改前 | 10,000 部改后 |
| --- | ---: | ---: | ---: | ---: |
| 首次进入，得到全部可见作品 | 1,202.28 | 897.24 | 7,861.79 | 2,556.31 |
| 重复进入，五次中位数 | 354.47 | 0.13 | 7,998.87 | 0.18 |
| 首次进入后，事件循环处理下一个事件 | 1,202.83 | 59.30 | 7,862.05 | 246.06 |

改前和改后每轮均返回 1,000 或 10,000 部作品。此外，用 400 组混合已识别和未识别作品的样本对比新旧分组代码，作品标题、顺序和成员均相同。

已有的组件基准直接传入已准备好的片库，首次布局显示 10 张卡片，五次取中位数。千条样本为 184.00 → 181.96 毫秒，万条样本为 179.79 → 172.48 毫秒。开发中间版两组一度测得 216.58 和 182.29 毫秒。这个基准只覆盖 Flutter 测试环境中的布局工作，屏幕点击体验以真实窗口结果为准。
