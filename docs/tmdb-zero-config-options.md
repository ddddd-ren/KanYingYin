# TMDB 零配置边界与后续路线

## 本期默认方案

看影音本期继续使用用户自己的 TMDB API Key。公共安装包不内置 TMDB Key，设置页输入的 Key 只交给看影音的安全凭据存储，不写入日志、刮削记录、导出资料包或媒体文件名。

没有 Key 或断网时，本地扫描和播放仍可用。TMDB 请求失败只影响标题、简介、评分、海报和季集资料的补充，不阻断本地媒体库浏览，也不会修改或删除原始视频、字幕。网盘索引和播放同样只使用用户已经配置的个人来源；删除索引或缓存不会触碰远端原始文件。

本期不依赖第三方桌面应用的本地接口，也不把第三方凭据、令牌或协议细节带入看影音。

## 后续路线一：官方或自建 HTTPS 代理

客户端可以只调用看影音定义的 HTTPS API，由服务端保存 TMDB Key、执行限流、缓存公开响应并统一处理端点故障。切换到这条路线前，需要另立服务端项目并完成：

- 身份认证、请求授权和密钥轮换设计；
- TMDB 请求配额、缓存失效和错误重试策略；
- 隐私政策、日志脱敏、数据保留期限和删除流程；
- 独立部署、监控、备份、成本和故障恢复。

这条路线可以减少首次配置，但会引入服务端运维、可用性和隐私边界。没有完成安全评审和独立部署前，不在公共客户端中启用。

## 后续路线二：继续用户自带 Key

客户端直接访问 TMDB 官方 API，用户自行创建和撤销 Key。该路线没有看影音服务端成本，凭据边界清晰，也能在断网时保留已经保存的资料；代价是首次使用多一步配置，并需要用户自行遵守 TMDB 的账号和配额要求。

本期默认选择路线二。未来若评估代理路线，必须保留无 Key 或断网时本地扫描和播放仍可用的行为，并继续保证 TMDB 刮削不会修改或删除原始视频、字幕。

## 数据保护约束

- 缓存只保存 TMDB 响应和必要的图片，不保存 API Key、Bearer Token、Cookie、远程路径或原始视频内容。
- `.kyymeta` 刮削资料迁移包不包含凭据；新设备需要先独立配置个人网盘来源。
- 清理 TMDB 元数据或海报缓存时，只清理看影音专属缓存，不删除视频或字幕。
